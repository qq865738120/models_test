# 鹈鹕骑车送布丁

提示词版本：pelican-prompts-5。本阶段预算：10分钟。

制作一段明亮、幽默的侧视SVG动画《鹈鹕骑车送布丁》，重点让角色真的骑在车上，动作与事件有清楚的先后。

在HTML中内联SVG，viewBox="0 0 640 480"。SVG只用SMIL或CSS动画，不使用JavaScript、外链或位图。画面只有一只白色鹈鹕、一辆完整的两轮自行车和一份布丁；长喙、喉囊与蹼足可辨，托盘固定在后货架。双翅扶住车把，身体始终坐在车上，双脚各自跟随相反相位的踏板，不能用脚在附近摆动代替接触。

一个周期6秒：0–2秒平稳骑行；2–3秒驶过减速带，车身轻颠；3–4秒布丁离开托盘再落回原位；4–6秒鹈鹕回头查看并恢复骑行姿态。轮转和地面运动表达前进。布丁不能穿过托盘，角色与车的连接不能因颠动或回头断开。

主体在所有运动极值都完整入画。连续三个周期无漂移，循环交界无突跳。自由设计配色、造型与背景，让颠簸、布丁腾空、回头三个事件一眼可读。交付前检查踏板四个相位、各事件边界及三个连续周期；简要记录实际检查和未完成部分。

## HTML 交付约定
最终入口为 `output/index.html`，脚本、样式、图片、数据与运行资源都在 `output/` 内，使用相对路径。本地静态HTTP和iframe均可使用，不依赖外网、父页面、固定端口或额外后端。已有构建工程用 `npm run build` 生成入口。
展示iframe只允许脚本、不提供同源身份；状态使用内存，不能依赖localStorage、IndexedDB或Service Worker。资源与ES模块由预览服务支持跨来源读取。

# 一万只鹈鹕的派单后台

提示词版本：pelican-prompts-5。本阶段预算：25分钟。

使用所附React + TypeScript起始工程，制作视觉美观、交互友好的《一万只鹈鹕的派单后台》。目标是具有成熟商业产品完成度的业务平台，不是功能控件拼凑的演示页。核心是查到真实订单、选择配送员、确认派单后保持各处数据一致，同时完成五个有实际作用的页面。

## 数据与布局
阅读materials/API.md和public/materials/reference.svg。使用提供的createMockApi()，整个应用共享一个实例，查询、详情、派单均经过它；切页不重建数据。固定10,000条订单，不另造数据或后台。生产页面从相对路径materials/mock-api.js引入。控制接口只用于自测。
默认进入“订单派送”。五页共享导航、标题、内容区和统一组件样式。订单页按参考图的深色侧栏、浅底、白卡、蓝色主操作与信息层级布局；1440×900下侧栏220px、顶栏72px、内边距32px、行高56px。窄屏可重排。

## 核心订单页
- 搜索编号/客户/地址，筛选all、pending、assigned、delivered；默认每页20条，只渲染当前页。显示真实总数、页码和总页数，边界翻页禁用。搜索/状态变化回第一页并清空选择，翻页清空选择。
- 表格包含选择、编号、客户、地址、状态、配送员和详情。只能选择当前页pending订单；全选不包含其他状态，数量准确，空选择不能派单。
- 批量派单先打开确认弹窗，展示数量并选择P01/P02/P03（鹈鹕一号/二号/三号）。未选配送员不可确认；取消不改订单且保留选择；提交期间不重复提交。失败保持数据原状与可重试上下文；成功关闭弹窗、清选择，并刷新列表、详情和统计。
- 点击详情打开右侧抽屉，展示真实完整编号、客户、地址、状态、配送员、优先级、创建时间、contents物品和note备注。无配送员/备注有明确占位。详情独立加载、失败重试和关闭。

## 其余四页及联动
总览：全部、待派单、配送中、已送达四张统计卡及状态分布图。点击待派单卡/去派单进入订单页pending第一页并清选择。
配送员：展示三名提供的配送员，每人“为TA派单”进入pending第一页并预选此人，仍需选择订单和确认。不要虚构运力或绩效。
运行报表：真实状态数量、占比及图表，标注当前会话快照、最后成功读取时间，提供刷新。总览/订单页共用统计；分别query四种status、page:1、pageSize:1读取total，同批结果更新，比例分母为全部订单，不随搜索变化。派单后使统计失效、再显示前刷新；加载不能伪装成0，失败不伪造更新时间。
设置：编辑每页20/50/100，保存后回订单第一页并清选择；未保存不生效。恢复默认只恢复20条，不撤销派单。页面切换保留设置，刷新整个应用恢复初始Mock与默认设置。提供说明和返回订单入口。
普通菜单切换保留已提交查询/状态/页码，清选择并关弹层。五页均有实际内容，不以同一表格换标题代替。

## 视觉美观与交互友好
在参考图的信息架构与布局基线上精修，不照搬成粗糙线框。五页、抽屉、确认框和各类状态要像同一款成品：字体层级清晰，字号、行高、8px间距节奏、卡片留白、圆角、图标与按钮一致；统计数字、状态标签、表格行列、长地址有稳定对齐。主操作突出，次要操作克制；色彩、阴影和动效服务任务，不靠装饰掩盖信息不足。没有大量空白占位、低对比小字、默认浏览器控件拼贴或调试面板。
让第一次使用者无需猜测也能完成派单：搜索和筛选含义清楚，可清除条件并回到全部订单；已选数量及当前可派对象明确，禁用操作能理解原因。批量确认清楚说明给谁派、派多少，取消/关闭保留合理上下文，不突然跳页或丢失筛选。
输入、悬停、焦点、禁用、加载、提交中、成功、失败均有一致的可见反馈。请求等待保持稳定布局与上下文，空态说明如何恢复，错误旁能重试，成功反馈与真实状态同步；不使用alert代替正常流程。详情阅读顺序合理，完整长地址可读，抽屉/弹窗关闭后能自然继续刚才操作。轻量过渡不能拖慢连续查找和派单，强动效应尊重减少动态偏好。

## 请求、反馈与验证
列表、详情和统计的加载/空态/错误/重试可辨。先发慢A、后发快B时，A的成功或失败不得覆盖B及其加载/错误状态。派单失败整批原子回滚；不以成功提示冒充实际提交。
390×844下导航、筛选、分页、派单、详情、设置可操作；表格可内部横滚，整页不溢出。键盘能完成主要流程；弹层焦点进入/返回、Esc关闭及背景防误操作有效。控件状态清楚，触控目标约40px，不将整页缩小。
实际走通总览→筛选→选择→派单→详情→统计更新，配送员预选、设置保存/恢复、失败重试和乱序查询。按API.md及tools/performance.js口径验证输入反馈P95≤100ms（排除API等待），不渲染全量DOM。记录实测与未测项目；无需为不存在的数据制作趋势、收入、登录或人员管理。

## HTML 交付约定
最终入口为 `output/index.html`，脚本、样式、图片、数据与运行资源都在 `output/` 内，使用相对路径。本地静态HTTP和iframe均可使用，不依赖外网、父页面、固定端口或额外后端。已有构建工程用 `npm run build` 生成入口。
展示iframe只允许脚本、不提供同源身份；状态使用内存，不能依赖localStorage、IndexedDB或Service Worker。资源与ES模块由预览服务支持跨来源读取。
交付前用本地静态服务检查实际成果。`output/DELIVERY.md`简要列出入口、启动方式、已检查与未检查项目和已知缺陷；不要求长报告，不能用占位页代替成果。

# 鹈鹕快递大作战

提示词版本：pelican-prompts-5。本阶段预算：45分钟。

使用所附Phaser 3起始工程，制作能正常操作并通关的《鹈鹕快递大作战》。使用统一关卡和SVG素材，重点是控制、碰撞、规则和完整的一局。

## 关卡与操作
阅读materials/START.md、CONTRACT.md、level.json、assets.json。用Phaser Scene、GameObject和物理实现游戏，不用视频或DOM演出代替。平台坐标为左上角，角色/机器人/快递为底部中心。不得移动快递、删障碍或改物理参数来降低难度。
方向键/A、D左右移动，空格跳跃，P暂停；手机提供左右、跳跃按钮。只在实体平台上允许跳跃，不可空中连跳。固定与移动平台都应实体碰撞；站在移动平台上随它往返，不能穿入平台。机器人按材料巡逻，不阻挡角色但接触受伤。用提供的待机、8帧/秒行走、跳跃和受伤素材反馈动作。

## 一局规则
开始后120秒、3点生命；重叠拾取三份快递，每份仅计一次。未集齐进入出口不能赢，集齐后进入出口胜利。机器人或危险区有效接触扣1命，随后0.8秒无敌，不能每帧扣血。角色完全越过世界下边界才算掉落，扣1命并回起点，普通快递进度和剩余时间保留。生命归零或时间归零分别失败。
开始前不计时；暂停冻结角色、机器人、移动平台、倒计时和无敌计时，恢复后连续。胜负结算后不再接受移动、收集或伤害；重开恢复起点、生命、120秒、全部快递及场景对象，不累积回调、输入或计时器。

## 界面与实玩
提供开始、游玩、暂停、胜利、失败界面；暂停可继续/重开，结算解释成功或失败原因并可重试。HUD准确显示生命、收集数、时间，操作与出口条件清楚。背景、可站平台、危险和快递可区分，使用统一卡通风格，收集/受伤有清楚反馈。
适配1280×720和390×844；允许保持画幅留白，HUD和手机按钮可读可达，触屏释放/移出按钮不粘键。镜头跟随且不越出地图。

## HTML 交付约定
最终入口为 `output/index.html`，脚本、样式、图片、数据与运行资源都在 `output/` 内，使用相对路径。本地静态HTTP和iframe均可使用，不依赖外网、父页面、固定端口或额外后端。已有构建工程用 `npm run build` 生成入口。
展示iframe只允许脚本、不提供同源身份；状态使用内存，不能依赖localStorage、IndexedDB或Service Worker。资源与ES模块由预览服务支持跨来源读取。

提示词版本：pelican-prompts-5。本阶段预算：60分钟。

使用所附Three.js + enable3d及本地Ammo资源，制作高画质的《鹈鹕叉车驾校》。目标是一款有精细模型、成熟材质灯光和完整视觉设计的实时3D小游戏，不能停留在几个方块、圆柱和球体拼成的功能演示。程序化建模后，由玩家真实驾驶、托起、运输和交付三个货箱。按materials/warehouse.json与CONTRACT.md的米制尺寸、Y向上坐标和布局实现，不导入外部模型/贴图，不改地图或货箱以简化任务。

## 精细建模与机械结构
可以选择写实或精致风格化的美术方向，但要有统一的设计和足够的几何层次。叉车从前、侧、后、斜上方观察都应成立，驾驶视角也应能看到实质细节：
- 车身有自然过渡的轮廓、分件面板与配重结构；补充格栅、灯具等工业细节，避免用一整块长方体代替全部车身。
- 四轮有真实厚度、胎面/侧壁层次、轮毂与轴心，不能只用无厚度圆片；驾驶室有立柱、顶架、座椅、方向盘和仪表区域，比例允许驾驶员实际坐入。
- 门架表现导轨、横梁、升降托架及液压/链条等可见机械关系；双货叉有厚度、叉根连接与前端形状，不能悬浮。非玩法要求的细部不必做完整机械仿真。
- 鹈鹕有身体体块、弯曲颈部、长喙、立体喉囊、眼部、翅膀/羽片层次与脚部，姿态自然；不能用“白球加黄三角”代替角色设计。身体与驾驶室、方向盘、座位无明显穿插。
- 仓库的货架有立柱/横梁/层板和结构层次，货箱有边缘、接缝/包装细节，地面有合理的安全线与区域标识。细节应服务尺度感和空间辨识，不增加阻挡原路径的障碍；原箱尺寸、货架与地图布局保持。
允许用自定义几何、倒角/曲面、程序化纹理或Canvas/SVG生成的本地纹理提高细节。不要通过重复堆小零件、无意义增加面数冒充精细；碰撞可用合理的简化刚体。
建立父子层级：轮子随前进/倒退滚动、转向轮偏转、货叉沿门架升降，驾驶员随车运动。用统一车宽参数协调可见部件和碰撞体；不要求精确悬挂或液压模拟。

## 材质、灯光与画面效果
车漆、金属货叉/门架、橡胶轮胎、座椅、羽毛和仓库地面应有可辨的表面差异；合理使用粗糙度、金属度与颜色层次，不把所有部件涂成同一种平面色。玻璃若采用，透明度与遮挡应正确。
设计有方向的主光、适当环境/补光与稳定阴影，让轮胎接地、货叉托举、货箱落地的空间关系清楚，避免悬浮感、阴影痤疮、全黑或过曝。正确处理颜色、曝光与抗锯齿，近看检查时不出现明显锯齿、闪烁或低清贴花。
整局保持统一的色彩、材质、场景尺度与UI风格；镜头有清楚构图和前后层次，能展示精细模型又不遮挡驾驶目标。可选雾效或后处理，但不以炫光、景深、特效数量替代扎实建模和清晰画面。高画质仍须在指定分辨率与性能条件下可操作。

## 驾驶与真实搬运
W/S前后，A/D转向，Q/E升降，空格制动，P暂停。由玩家控制，不能用自动路线/预录动画代替。车与箱子同地面、墙和障碍合理碰撞。
