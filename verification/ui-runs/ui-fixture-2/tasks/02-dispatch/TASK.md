# 一万只鹈鹕的派单后台

本阶段预算：25分钟。

依据参考图完成鹈鹕配送派单后台，使用所附React与TypeScript项目。
实现搜索、状态筛选、分页、当前页批量选择和派单、订单详情抽屉。搜索、筛选、分页由提供的浏览器内Mock接口处理；筛选变化回到第一页并清空选择，切页清空选择。
以1440×900参考图为桌面视觉目标；390×844手机宽度不得出现整页横向溢出，主要操作保持可达。
处理加载、空结果、接口失败和重试。快速切换条件时只能显示最后一次查询的结果。批量派单失败要恢复原状态并显示错误，成功后页面与服务端一致。
在指定设备、生产构建和固定采样脚本下，搜索输入到下一次可见反馈的P95不超过100ms，不含请求等待；整页不得一次渲染10,000条记录。验收脚本和阈值已附。
提交代码、启动命令、验证结果与已知问题。
使用 public/materials/mock-api.js 的 createMockApi()；接口见 materials/API.md。每个页面独立持有Mock状态，不连接固定端口服务。

## HTML 交付约定
最终入口必须为 `output/index.html`。图片、脚本、样式、数据与物理运行资源全部存于 `output/` 内并使用相对路径引用。页面应能通过普通本地静态HTTP服务打开，也能在iframe中运行；不依赖外网、宿主父页面、固定端口、外部API或额外后端进程。允许使用多个本地资源文件。
React/Phaser/Three.js项目执行 `npm run build` 生成该入口，已有构建配置使用相对资源路径。研究题制作含方法、图表、原始结果链接与结论的HTML报告；SVG题在HTML中内联动画，SVG内部仍不得使用JavaScript。
交付前用本地静态服务检查实际功能。另写 `output/DELIVERY.md`，说明成果路径、启动方式、已运行检查、未运行检查和已知缺陷。不要以占位页或原始起始页代替成果。
