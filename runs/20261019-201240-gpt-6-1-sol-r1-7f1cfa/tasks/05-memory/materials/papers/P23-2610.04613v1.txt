Multi-Yoked Surface Codes
Yuga Hirai 1, 2,∗ and Yasunari Suzuki 2,†
1Department of Applied Physics and Physico-Informatics, Keio University, Kanagawa, Japan
2Center for Quantum Computing, RIKEN, Saitama, Japan

The surface code is the leading candidate for fault-tolerant quantum computation owing to its
planar nearest-neighbor connectivity, high threshold, and efficient decoding, but its low encoding
rate demands on the order of a thousand physical qubits per logical qubit in the teraquop regime.
Yoked surface codes improve the density by a factor of two or three by concatenating a high-density
parity check code on top of the surface code while retaining planar nearest-neighbor connectivity.
In this work, we generalize this idea to multiple levels of concatenation and introducemulti-yoked
surface codes. Our construction rests on two new ingredients. First, we propose a family of outer
codes calledchain codes, built by chaining copies of aseed codethat detects the block errors of
the code one level below; the resulting codes use all logical qubits of the lower level and achieve a
high encoding rate within a few concatenation levels. Second, we design a patch allocation in which
movable workspaces perform the yoking checks by lattice surgery with a hierarchy of yoking intervals,
so that lower-level checks are performed frequently while higher-level checks are performed less often,
which avoids the long yoking intervals that a single large-distance outer code would require. As a
benchmark, we construct a three-yoked surface code with a [[256,166,8]] outer code and evaluate
it numerically under the SI1000 noise model using soft information from the surface code decoder.
The logical error rate is suppressed exponentially in the inner code distance, and in the teraquop
regime the three-yoked surface code is about 4 to 4.5×denser than the unyoked surface code.
I. INTRODUCTION
Quantum computers require error correction during computation as physical qubits are highly susceptible to
bit-flip and phase-flip errors. The surface code is considered one of the most promising quantum error-correcting
codes [1–4] because it has several preferable properties: it can be implemented with only nearest-neighbor planar
connectivity on a square lattice [5, 6], it has a high threshold of∼0.01 [7–9], and its simple structure enables
efficient decoding with the minimum-weight perfect matching (MWPM) algorithm [2, 10–12] and computation of
soft information [2, 13, 14]. The surface code has already been demonstrated in real devices, and logical error
suppression under realistic device noise has also been experimentally confirmed [5, 15]. Despite these advantages,
the surface code has a serious drawback: a low encoding rate. Executing a quantum algorithm in the teraquop
regime requires a logical error rate per surface-code patch per round below 10−15 [16]. Assuming 10 −3 physical error
rates, this means that a single surface-code patch requires on the order of a thousand physical qubits, including
measurement qubits. Therefore, proposing high-density memory space with reasonable hardware requirements is
essential for realizing fault-tolerant quantum computation.
There have been many studies aiming to improve the density of memory space, such as quantum low-density
parity-check codes and concatenated codes. However, almost all of them impose additional hardware requirements,
such as non-nearest-neighbor interactions, high-degree connectivity, deeper syndrome-extraction circuits, or more-
than-two-dimensional embeddings [17–22]. These requirements might incur penalties in physical error rates, device
scalability, and decoding performance. Thus, methods to improve the density without additional requirements have
been lacking.
Recently, yoked surface codes [13] have successfully improved density by 2 to 3×without imposing any additional
requirements described above. Ref. [23] also improves the density by using a sophisticated arrangement of twist
defects. A key idea in their improvements is to concatenate a single high-density parity-check code, such as an
[[n, n−2,2]] iceberg code, over the surface-code qubits. In traditional constructions of general concatenated codes,
many ancillary code blocks must be allocated for fault-tolerant syndrome extraction, and this overhead undermines
the advantage of concatenated codes in meaningful regimes. The yoked surface code eliminates this overhead by
performing syndrome extraction of the concatenated code with a carefully designed lattice-surgery sequence with a
small workspace.
In this work, we proposemulti-yoked surface codes, which achieve higher density by concatenating multiple
high-density parity-check codes over the surface codes. Specifically, we find that a three-level concatenation, i.e.,

First, the multiple concatenations of high-density parity-check codes introduce complicated correlated errors in

design efficient workspace allocations and syndrome-extraction schedules for outer codes. This work addresses both

We resolve the first problem by proposingchain codes, which generalize the mechanism of theC 4/C6 code [26].
Here, theC 4 code is a [[4,2,2]] iceberg code, and theC 6 code is a [[6,2,2]] non-iceberg code. Although two logical

surface codes, we use surface-code qubits instead of physical qubits, and use general [[n, n−2,2]] iceberg codes
instead ofC 4 codes. To detect correlated errors in the iceberg codes and their underlying inner codes, we propose a
framework namedchain codes, which can detect all correlated errors in each lower-level code block as theC 6 code
does. When we want to define chain codes for multiple blocks of a given inner code, we first find a smallseed code
that can detect all problematic errors in one code block. Then, we construct the chain code by chaining copies of
the seed code as shown in Fig. 7. We consider up to three-level concatenation for a benchmark in this work; this
yields an outer code [[128n 2,104n 2 −42,8]], whose encoding ratek/nis∼0.65 forn 2 = 2 and∼0.80 forn 2 = 20.
For the latter problem, we present an efficient memory-space implementation of the multi-yoked surface code. We
separate the whole layout into several modules, allocate workspaces for each high-density parity-check code in the
outer code, and move them to perform syndrome extractions. An example layout is shown in Fig. 10. This layout
not only enables parity checks for outer codes but also allows fine-tuning of the trade-off between space overhead
and theyoking interval, that is, the time between two consecutive yoking operations. In the original yoked surface
code, a space-efficient implementation with a single hallway shown in Fig. 8 was adopted for yoking to minimize
the space overhead. When the outer code distance becomes larger, however, this design easily lengthens the yoking
interval, which in turn requires larger surface codes to tolerate idling errors. Thus, it may achieve high density
only in a regime of logical error rates far lower than those required in practice. In our layout, we adopt both time-
efficient and space-efficient yoking designs to balance the frequencies of the checks of each level and the number of
workspaces. This allows us to use the qubits spent on excess suppression to make the code denser. Note that hook
errors in physical syndrome-extraction circuits for this procedure can be systematically eliminated without losing
the fault distance by using the technique from our previous work [27].
We numerically simulated the performance of the multi-yoked surface code with a gap simulation similar to
Ref. [13], and optimized parameters for target logical error rates. We find that, with an inner code distance of
dinner = 10, it is about 4 to 4.5×denser than conventional surface codes under the SI1000 noise model, which
corresponds to a 1.3 to 1.5×density improvement over the yoked surface code. We note that the simulated three-
yoked surface code is only a prototype; a more elaborate design, or concatenation beyond three levels, may yield
an even higher density.
Finally, we note a drawback of our multi-yoked surface codes compared to the original yoked surface code, although
we believe it can be resolved. In the yoked surface codes, both inner and outer codes are matchable, and they can
be simultaneously decoded with fast MWPM decoders. In our case, while level-0 and level-1 codes (i.e., surface
codes and iceberg codes) are matchable, the outer codes (i.e., chain codes) are not. Therefore, we need to decode
the inner parts with MWPM decoders, and then decode outer codes with other methods. We believe, however,
that this does not pose a serious problem in the whole architecture. This is because the outer code is small and its
syndrome-extraction frequency is much lower than that of the inner codes. Thus, we believe its real-time decoding
would be feasible, for example, with beam-search-based decoders [28]. Architecting such a two-stage decoding in
realistic systems goes beyond our scope and is left as future work.

II. PRELIMINAR Y
Multi-yoked surface codes are based on a concatenated code whose level-0 code is the surface code. In this section,
we review the basics of surface codes and concatenated codes, both of which are needed in what follows.
A. Surface Codes
The surface code [1–4] is a stabilizer code defined on a square lattice, where the data qubits sit on the vertices,
and both the Z and the X stabilizers sit on the plaquettes in the checkerboard pattern shown on the left in Fig. 2.
Each plaquette has its own measurement qubit, which extracts the parity of the neighboring data qubits. We call a
boundary terminated by X (Z) stabilizers anX boundary(Z boundary), and an X (Z) logical operator is defined as a
chain of X (Z) operators on the data qubits connecting the two X (Z) boundaries. A single patch therefore encodes
one logical qubit. The surface code has several attractive properties. First, it requires only planar, nearest-neighbor
connectivity on a square lattice, which relaxes the demands on the device. Second, it has a high threshold of∼0.01.
Third, it can be decoded relatively easily by the minimum-weight perfect matching (MWPM) algorithm [10], since
every error in the decoding graph can be represented by an edge; a hyperedge corresponding to a Y error is
decomposed into the edges corresponding to X and Z errors without significantly degrading the decoding accuracy.
We call stabilizer codes with this propertymatchable.

During the computation, the Z and X check operators are repeatedly measured using the ancillary qubits placed
at the center of the check operators. If we assume a circuit-level noise model, i.e., a model in which Pauli errors are
inserted for each physical gate and idling operation, Pauli errors during parity measurements might propagate to
multiple data qubits; such errors are called hook errors. With a carefully designed order of CNOT gates, these hook
errors do not reduce the fault distance [27, 29, 30]. This is another advantage of surface codes, as the concatenated
codes discussed later require large overheads for fault-tolerant parity checks.
Since the surface code has a simple structure, it can be expressed by more abstract diagrams. One of them is
thedefect diagramshown in the right panel of Fig. 2. The red (blue) walls represent the X (Z) boundaries, and
the empty space enclosed by the walls is the bulk of the surface code, where the stabilizers are defined. The logical
operators in this diagram are defined in the same way as before: they are chains connecting two disjoint walls of
the same Pauli type. In short, the diagram represents the spacetime trajectory of a surface code patch, and it
can describe various operations. When we are restricted to nearest-neighbor interactions, logical operations are
performed by a technique called lattice surgery [31, 32]. Lattice surgery can be executed by merging two surface-
code patches into one and then splitting it back into two, as shown in Fig. 3. In this figure, the two patches are
merged along their X boundaries, so the operation realizes a joint ZZ measurement between them. Patch rotation
and movement can also be regarded as forms of lattice surgery. As we will see later, all the stabilizer measurements
of outer codes are realized by this lattice surgery operation on the surface code.

When we decode errors in the surface code, we can calculate, as a byproduct, soft information, which quantifies
how confident the decoder is in its estimate for given syndrome values. One such piece of information is called the
complementary gap[13, 33, 34], which is defined as the log-likelihood ratio between the minimum-weight matching
and the minimum-weight matching in the complementary logical class. In the multi-yoked surface code, such a value
is assigned to each edge of the outer-code decoding graph. Note that the computational complexity of evaluating
the complementary gap grows exponentially as the number of logical qubits increases. Recently, it has been shown
that this overhead can be avoided by using a different soft-information measure that is similar to the complementary
gap [14].
B. Concatenated Codes andC 4/C6 Codes
Concatenated codes are codes in which qubits are recursively encoded into quantum error-correcting codes [24–
26, 35–37]. Here, the concatenation level is counted starting from the physical qubits. One of the best-known
examples of concatenated codes is theC 4/C6 code introduced by E. Knill [26, 36]. This code consists of two types
of codes. One is the [[4,2,2]]C 4 code, and the other is the [[6,2,2]]C 6 code. TheC 4/C6 code first encodes physical
qubits with theC 4 codes, which are recursively encoded withC 6 codes. Fig. 4 shows the code construction.
In general, encoding more than one logical qubit per block may cause correlated error events at the higher level,
and the code distance does not necessarily scale asd lowerdhigher, whered lower andd higher are the code distances of
the lower- and higher-level codes. We call such correlated errorsblock errors. A simple solution to this problem is
to distribute thei-th-level logical qubits across different code blocks at level-(i+ 1). However, this increases the
minimum number of physical and logical qubits required to achieve a target logical error rate and is not suitable
for practical implementation. TheC 4/C6 code resolves this problem by letting theC 6 code detect such block errors
on a pair of logical qubits, and its code distance does scale asd lowerdhigher. The code distance of theC 4/C6 code
therefore scales as 2 N, whereNis the number of concatenation levels.

Unlike surface codes, a naive implementation of parity measurements of concatenated codes is not fault-tolerant
due to hook errors, and we need to introduce techniques to fault-tolerantly measure parities. One well-known
method is Knill’s error correction, which implements parity measurements using the Knill gadget [26, 36]. In this
gadget, the parity measurements are performed by state teleportation, which consumes logical Bell pairs at each

level of concatenation. Therefore, we have to prepare verified Bell pairs in advance. Because this generation uses
error detection and post-selection, it introduces significant spacetime overhead. Other approaches, such as Shor’s
and Steane’s error correction, also introduce similar overheads.
Concatenated codes with higher encoding rates than theC4/C6 code have been extensively explored. For example,
Refs. [24, 25] achieved a constant space overhead in the asymptotic limit of many concatenation levels. However,
the overheads from syndrome-extraction gadgets might significantly degrade the density in the practical regime.
Therefore, achieving high-density memory-space on a square-grid qubit array is still challenging. Recently, Ref. [38]
has proposed concatenating Reed–Solomon codes on top of bivariate bicycle codes, each encoding 12 logical qubits,
by treating each lower-level block as a qudit. Although this enables simple concatenation that is tolerant to block
errors, this approach requires the outer code to detect all qudit errors. As we will explain later in Sec. IV A, our
proposal, the chain code, detects only problematic errors among them.
III. EXISTING WORK: YOKED SURF ACE CODES
Multi-yoked surface codes are heavily based on the idea of yoked surface codes by C. Gidneyet al.[13]. In this
section, we introduce their concept and explain our strategy to further improve the density.
A. Y oked Surface Codes
There are many ideas to improve the density of the normal surface code. However, almost all ideas impose
strong hardware requirements, such as non-nearest-neighbor interactions, high-degree connectivity, and more-than-
two-dimensional embeddings. Yoked surface codes need none of them; they require only nearest-neighbor planar
connectivity on a square lattice. This connectivity has already been realized in real devices [5, 15].
The strategy of the yoked surface codes for densifying the surface codes is to concatenate a high-density code
on top of them. We refer to the surface code as theinner codeand to the concatenated code as theouter code.
Yoked surface codes employ iceberg codes or quantum parity check codes as the outer code ford outer = 2 and
douter = 4, respectively. The left panel of Fig. 5 shows check operators of the [[6,4,2]] iceberg code and logical
Pauli operators for four logical qubits. The parity measurements of the outer code in the yoked surface codes
are performed by lattice surgery on the surface codes, as shown in the middle panel of Fig. 5. The probability
of causing correlated errors across multiple surface codes, which are analogous to hook errors in the conventional
approaches, is sufficiently suppressed by widening the lattice surgery path. The widened paths are extended along
the time direction rather than the spatial directions, so as to minimize the workspace needed for the parity checks,
as shown in the right panel of the figure. The lattice surgeries for the different checks are arranged sequentially
along the time direction. This construction enables more space-efficient concatenation of high-density parity-check
codes than syndrome-extraction gadgets in conventional concatenated codes. With this syndrome extraction, both
inner and outer codes become matchable. Therefore, they can be decoded simultaneously using MWPM decoders
by assigning the detectors of the outer code to the corresponding boundary detectors of the inner code.

B. Open Questions W e Address
To further improve the density of the yoked surface code, we should increase the distance of outer codes with
high encoding rates and reduce the distance of inner surface codes with low encoding rates. There are two ways to
increase the outer code distance: one is to use a single code with large distance, and the other is to use a multi-level
concatenated code.
Ref. [13] already pursued the former approach by replacingd outer = 2 iceberg codes with ad outer = 4 quantum
parity check code. However, they did not go beyond distance four because increasing the outer code distance
does not work straightforwardly for the following reasons. If we increase the code distance of the outer code, the
number of outer checks increases. This makes the interval between two subsequent parity measurements of the
outer codes longer. This will eventually increase the idling errors of surface-code qubits and degrade the overall
performance. Although this can be mitigated by increasing the inner code distance, this contradicts the original
motivation to decrease the inner code distance. Also, increasing the inner code distance makes the available total
code distanced innerdouter highly discretized, and typically leads to excessive logical error suppression below what is
actually required. The qubits spent on this excess suppression could instead be used to make the code denser.
Therefore, this paper explores the other direction: increasing outer-code distance by further concatenatingd= 2
high-density parity check codes over the yoked surface codes. This direction is promising because logical error rates
of qubits encoded with the level-0 (surface) and level-1 (iceberg) codes are suppressed, and the required interval of
the additional outer-code checks can be much longer than that of the iceberg codes. Thus, further concatenations
are expected to have little effect on the lower-level check intervals. Our research question is therefore “How much
can we improve the density of the yoked surface code by increasing the concatenation level?”
To address this question, we need to resolve two difficulties. First, if we use a concatenated code as the outer code,
its upper-level codes must manage block errors in lower-level codes. Although theC 6 code satisfies this property,
it is an open question whether we can satisfy this criterion for a lower-level code encoding more than two logical
qubits. Second, even if a series of high-density parity check codes exists, it remains open whether they can be
implemented on a square-grid lattice with modest workspace overhead. We address these two open questions by
proposing chain codes and memory-space layouts tailored for multi-level concatenated codes.
IV. MUL TI-YOKED SURF ACE CODES
We now introduce multi-yoked surface codes, which concatenate additionald= 2 codes on top of the yoked surface
codes. The multi-yoked surface code is built from two new components: a family of codes called chain codes, and a
memory-space layout of the surface-code patches. We consider up to 3-level concatenation for multi-yoked surface
codes. The code thus consists of level-0 surface codes, level-1 iceberg codes, level-2 chain codes, and level-3 chain
codes. Below, we introduce the framework for chain codes and show a construction of level-2 and level-3 chain codes.
Then, we show how to allocate surface-code patches to achieve high density and overall memory-space construction.
A. Chain Codes
In Subsection II B, we introduced theC 4/C6 code, in which aC 6 block detects the block errors of the three
C4 blocks one level below. In this subsection, we generalize this concept by constructing a code that can detect
all single block errors of the iceberg codes one level below, as shown in Fig. 6. We concentrate on distance-two
CSS codes concatenated on top of the iceberg code. Note that hook errors during parity checks are discussed in
Sec. IV D, so we ignore the hook errors in this subsection. Also, we assume that Z errors and X errors are estimated
independently, and that X and Z errors are detected by Z and X checks, respectively. Therefore, without loss of
generality, we focus on the mechanism of detecting X errors with Z checks.
Suppose level-1 to level-(i−1) concatenated codes constitute an [[n, k, d]] code, and we want to construct a
level-icode with distance two that is concatenated overrcopies of them. We call every logical X error that can be
induced by a weight-(2d−1) undetectable X error on level-0 (i.e., surface-code qubits in the multi-yoked surface
code) qubits aproblematic errorand denote their set byP prob,X ⊂ {I, X} ⊗k. Next, we list an independent set
of Pauli Z operators that can detect all the problematic errors. We call this set of Pauli operators aseed code

C. Finding a Level-3 Chain Code on the Level-2 Chain Code
Next, we construct a level-3 chain code over level-1 iceberg and level-2 chain codes. We expect the combination
of level-1 and level-2 codes to tolerate up to three Pauli errors in surface-code qubits. As the size of the level-2 chain
code is typically large, a brute-force approach does not work. Instead, we employ the following heuristic procedure
to find a seed code for high-rate level-3 chain codes.
We assume that the level-1 iceberg code and level-2 chain code constituteklogical qubits per block. Our heuristic
exploration for the level-3 code runs with a positive input parametercas follows. First, we choose a classical code
[k, k−c, d] with the largestdfrom a code table [39]. We use this code’s parity-check matrix as the seed code for
both Z and X errors. Then, we iteratively permute an assignment ofklogical qubits in the level-2 codes to the
input of the level-3 seed code. In each trial, we compute the distance of the chain code generated from the level-3
seed code. If the distance reaches eight, the procedure stops and outputs the chain code. If not, the procedure
aborts. While smallcresults in a high-rate level-3 code, this procedure aborts with high probability if the chosen
cis too small. Therefore, we start with smallcand iterate to largercuntil we find a solution.
D. W orkspace Design and Y oking Interval
As in the yoked surface code, the multi-yoked surface code reserves workspaces in which the lattice surgeries for
yoking are performed; no logical qubits are encoded there. A workspace admits two designs, a time-efficient one
and a space-efficient one, both shown in Fig. 8, which depicts the defect diagram during yoking as seen from the
side. Which version to use for each check depends strongly on the outer code design; we describe our choices in
Sec. IV F. In the time-efficient version, the CNOT scheduling of the surface code must be designed carefully, because
this lattice surgery presents vertical and horizontal X (Z) boundaries at the same time, which may give rise to hook
errors in the surface code. As shown in our previous work [27], however, such hook errors can be avoided in a
hex-grid implementation.
The surface-code patches are allocated as shown in Fig. 9. Several workspaces are placed to perform yoking,
i.e., parity checks for outer codes with lattice surgery. Since most patches are not adjacent to a workspace, the
workspaces move up and down through the memory-space to reach them. To keep the memory dense, the number
and size of workspaces should be as small as possible, which means that not all patches can be yoked simultaneously;
instead, each patch is yoked periodically. If the width of the yoking is too small, a hook error on outer codes can
occur during the lattice surgery for outer-code checks, which can reduce the fault distance of outer codes. To
avoid this problem, choosing a yoking width ofd innerdouter is sufficient, as logical errors with weightd innerdouter are
acceptable regarding the target logical error rates. However, this is only a sufficient condition, and we can further
reduce the width if the outer codes are designed to tolerate hook errors. In fact, as we will explain in Sec. IV F, we

The yoking intervals must also be designed carefully to achieve a small logical error rate while keeping the

yoking interval degrades the logical error rate even when all the other checks at that level have short intervals.
Since the concatenated code has a hierarchical structure, we can design the multi-yoked surface code so that the
lower-level checks are performed more frequently and the higher-level ones less frequently. This flexibility in the
check schedule is key to significantly reducing the logical error rate of multi-yoked surface codes, which in turn
improves the density.

V. NUMERICAL RESUL TS
A. Evaluation Methods and Approximations
We have evaluated the performance of the proposed memory-space implementation. The full circuit is too large
to simulate directly in Stim [41], so we utilized the following evaluation methods and approximations. Hereafter,
we denote the surface code distance byd.
The outer codes in the multi-yoked surface codes are not matchable, and we cannot handle the whole decoding
task with fast MWPM decoders. Thus, the inner and outer codes are simulated separately. We first evaluate the
logical error events of the idling circuits of the inner surface codes. Then, the outer code simulation is executed
with gap values pre-sampled from them and decoded with Tesseract [28]. This approximation simplifies decoding
for the outer codes and is necessary to make the evaluation feasible with our computational resources.
In the evaluation of outer codes, we ignore the following errors in outer codes that are not expected to contribute
significantly to the final logical error rates, similar to Ref. [13]. The hook errors occurring in the outer-code
checks are ignored because we allocate sufficient workspace width and the number of logical error events involving
such errors is negligible. Since the time-like edges corresponding to the measurement errors did not contribute
significantly to the logical error rates as discussed in Ref. [13], we assume perfect syndrome extraction for outer
checks. Spacetime-like edges arising from the different schedules of the lattice surgery operations are ignored in the
gap simulation. We expect this to have a negligible effect on the final logical error rates, since such error events are
very rare.
We utilized Monte Carlo sampling for evaluating logical error rates. As the evaluation for logical error rates in
the teraquop regime requires massive sampling, we utilized several computational resources in parallel. We used
a workstation with two Intel Xeon Platinum 8173M CPUs (56 cores, 112 threads, 2.0 GHz base, up to 3.5 GHz)
with 256 GB memory, and 22 compute nodes of the RIKEN R-CCS Cloud: 14 nodes, each with an AMD EPYC
9684X CPU (96 cores, 192 threads, 2.55 GHz base, up to 3.7 GHz) and 768 GB memory; 2 nodes, each with two
Intel Xeon Platinum 8470 CPUs (104 cores, 208 threads, 2.0 GHz base, up to 3.8 GHz) and 2,048 GB memory; 4
nodes, each with two AMD EPYC 9554 CPUs (128 cores, 256 threads, 3.1 GHz base, up to 3.75 GHz) and 1,536
GB memory; 1 node with two AMD EPYC 9534 CPUs (128 cores, 256 threads, 2.45 GHz base, up to 3.7 GHz) and
1,536 GB memory; and 1 node with an Intel Xeon w9-3575X CPU (44 cores, 88 threads, 2.2 GHz base, up to 4.8
GHz) and 512 GB memory.
B. Evaluation of Inner Codes
First, we sampled the surface code data. The syndrome extraction circuit for 12drounds is constructed using the
hex-grid scheduling of Ref. [27] to avoid all hook errors in it. We applied the noise model SI1000 [13] with physical
error ratep= 10 −3. The memory circuit does not include errors in reset or measurement operations for data
qubits, since multiple copies of this circuit are stacked as building blocks to construct the gap simulation circuit.
We used Stim [41] for generating circuits and detector error models, and errors are decoded by PyMatching [10]
with two-pass decoding [12]. The gap values are then calculated on the decoding graph updated by the results of
the first-pass decoding.
Histograms of sampled gap values are shown in the left panel of Fig. 14 for several inner-code distances. Note
that a positive gap value means that the decoder’s estimate was correct, and a negative value means that it was
incorrect. Similar to the results in Ref. [13], we see the distribution becomes smooth as the code distance increases.
We then calibrated the gap for the outer decoder by fitting the log-likelihood ratio of an inner-decoder logical
error as an affine function of the gap, Λ aff(g) =αg+β, whereαis the scale andβis the offset, by minimizing the
log-loss over the samples. Such a fit is dominated by the many low-gap samples, so we sorted the samples by gap,
cut them into bins each containing a fixed number of observed or affine-predicted logical errors, and in each bin
shifted the affine line by the shrunk log ratio of observed to predicted errors. The shifted points were monotonized
and linearly interpolated, and the result was adopted only when it beat the affine fit on held-out log-loss. The
results are shown in the right panel of Fig. 14. This figure shows the logical error rates for observed unsigned gap
values and their fit. We see that the gaps are well calibrated.

F. Density Evaluation
We finally compare the number of physical qubits in each code, which is shown in Fig. 18. In this evaluation, we
use the fitted logical error rates logp L =−0.4661d−1.566, logp L =−0.794d+ 0.625, logp L =−1.5664d+ 6.2812,
and logp L =−2.8747d+ 12.2164 for the unyoked, one-yoked ([[16,14,2]]), two-yoked ([[16,14,2]]→[[112,104,2]]),
and three-yoked surface codes ([[16,14,2]]→[[112,104,2]]→[[208,166,2]]), respectively. The physical qubit count
per logical qubit in the above evaluation includes the qubits used for workspaces, and we assumed the memory-space
layout discussed in Sec. IV F as shown in Fig. 19.
Before discussing this figure, we note two caveats about this evaluation. First, these memories serve as cold
storage, and we do not include hallways for load and store operations between the memory and the computational
space. If load and store functionality were required, the density would decrease slightly from the shown value. We
nevertheless omit them to focus on the achievable density of storage. We later discuss candidate designs for data
extraction in Sec. VI. Second, we used the same layouts for two-yoked and three-yoked surface codes. As our patch
layouts are optimized for the three-yoked surface code, the performance of the two-yoked surface code is likely
underestimated.
As can be seen from the figure, the three-yoked surface code significantly reduces the number of physical qubits.
Suppose that a teraquop regime requires a logical error rate per inner round of less than about 10 −15. Then, our
three-yoked surface code is about 4 to 4.5×denser than the unyoked one in the teraquop regime.
VI. DISCUSSION
In this work, we generalized yoked surface codes to a multi-level concatenated version, which we call multi-yoked
surface codes. We constructed a new code family, called chain codes, to obtain the high-density parity-check codes
that fit our multi-yoked construction. The chain codes have the favorable property that they can be concatenated
over a code while managing correlated errors inside each block. Therefore, they enable a high-density encoding
even with only a few concatenation levels. We also solved the long-interval problem, which arises when a single
large-distance code is used as the outer code, by introducing a hierarchy among the yoking intervals at each level.
By making the higher-level yoking intervals longer, we can keep lower-level yoking frequent. Under the SI1000 noise
model, we confirmed that our three-yoked surface code shown in Fig. 13 is about 4 to 4.5×denser than the unyoked
surface code in the teraquop regime. This achieves a higher density than the original yoked surface code.

There are several future directions to further improve the idea of multi-yoked surface codes. We list our current
open questions and future perspectives as follows.
Can we further improve the density by higher-level concatenation?This work considered up to three-
yoked surface codes because simulating higher-level concatenation requires significant classical computational re-
sources. With more computational resources, we might see that the density of multi-yoked surface codes improves
further.
Can we efficiently evaluate the performance of high-density and teraquop-regime memory?Simulat-
ing the entire memory is a major bottleneck in designing memory spaces for the teraquop regime, yet these designs
should be completed before building the actual quantum memory. Exploring more sophisticated and accurate
methods to evaluate logical-error-rate behavior in the teraquop regime is a vital topic.
Can the outer decoder really keep up with the outer syndrome extraction?A major drawback of using
multi-yoked surface codes is that the outer code becomes non-matchable, so we cannot use fast MWPM decoders
such as PyMatching. We expect this problem can be mitigated by employing two-stage decoders with carefully
optimized parameters, but this goes beyond the scope of this paper and is left as future work.
How should we design the timing of data load/store in accordance with both the yoking and the
computation?This paper focuses on memory operations for the multi-yoked surface code and does not account
for the workspace needed for load and store operations between the memory and hot storage or the computational
space. Although data can be transferred to and from external code blocks via state teleportation using lattice
surgery, the hallway design for this lattice surgery is not obvious, for the following reasons. Supposing the required

[PDF page 18]
18
fault distance isd outerdinner, the workspace for lattice surgery should haved outerdinner width andd outerdinner rounds
of syndrome extraction. Therefore, unlike yoking operations, which tolerate time-like errors during lattice surgery,
this operation cannot easily use a space-efficient implementation to reduce the workspace width. This problem
can be resolved by separating a single lattice surgery withd outerdinner rounds into several lattice surgeries with
fewer rounds, and by employing a space-efficient implementation for each lattice surgery. Errors in the operation
are estimated using the soft information from the inner decoder. An example design for extracting data while
preservingd outer = 4 by splitting the extraction into two lattice surgeries is shown in Fig. 21. Optimizing the
schedule of these separated lattice surgeries would be necessary to combine our ideas with computational space.
How should such a memory be connected to the hotter memories without incurring significant
latency?Compared to the original yoked surface code, our multi-yoked surface codes provide colder memory,
i.e., higher-density memory with longer access latency. This does not conflict with yoked surface codes; instead,
we envision using them complementarily to form a continuous memory hierarchy. Exploring efficient memory-
hierarchy designs and latency-hiding techniques would be a promising direction, given progress in modern computer
architectures.
Is there an efficient procedure for constructing chain codes for a general level of concatenation?
Several of our protocols, such as finding seed codes for given problematic errors and optimizing the weight of given
codes with yoking-weight reduction, rely on heuristic methods. Because we focused on concatenations of small
high-level codes, we found solutions that we believe are near-optimal. However, it remains open whether better
search algorithms exist. This exploration might improve the construction and implementation of the multi-yoked
surface codes.
