Modular Neural Decoder for Surface Code Memory
and Logic on Superconducting Processors
Moritz Lange, 1,∗ Ole Fjelds˚ a,2 Gustaf Jonasson Johansson, 2 and Mats Granath 1,†
1Department of Physics, University of Gothenburg, Gothenburg, Sweden

Neural decoders for quantum error correction have achieved high accuracy on surface code mem-
ory experiments, but practical fault-tolerant computation requires decoders that transfer across
devices, noise conditions, and logical operations. We introduce a modular graph-recurrent decoder
designed for this setting. Built from reusable local syndrome encoders, it is pretrained in simula-
tion and fine-tuned to hardware using a common pipeline, with only lightweight spatial aggregation
adapted between experiments. The decoder performs competitively on conventional memory bench-
marks, outperforming minimum-weight perfect matching (MWPM) at distances 3 and 5 on an
IBM Nighthawk-generation processor and closely approaching AlphaQubit [1] on Google’s below-
threshold hardware data [2]. We then test the framework in two settings beyond memory decoding
on the same IBM device. First, in anX-type stability experiment, we continuously tune the effective
measurement error rate using a variable pre-readout rotation and train a single decoder jointly across
the resulting noise range. It matches or outperforms MWPM across the sweep without requiring a
separately calibrated decoder for each setting. Second, we decode aZZ-merge lattice-surgery ex-
periment between two distance-3 surface-code patches, improving the decoded correlation between
the merge outcome and the finalZZparity relative to MWPM on real hardware. Together, these
experiments demonstrate neural decoding that is portable not only across hardware, but also across
qualitatively different surface code observables and logical operations, using models trainable on
single-GPU academic resources.
I. INTRODUCTION
Quantum error correction (QEC) encodes logical in-
formation redundantly in many physical qubits and ex-
tracts error information through repeated stabilizer mea-
surements [3–5]. The surface code is a leading candidate
for superconducting processors, and recent experiments
have demonstrated the key milestone of operation be-
low threshold: logical error rates that decrease as the
code distancedgrows [2]. Realizing this suppression in
practice, however, depends, among other things, on the
classical decoder, the algorithm that infers logical cor-
rections from the measured syndrome record: decoding
Google’s distance-7 memory experiment [2] with plain
minimum-weight perfect matching on the basic pairwise
pij-calibrated prior gives an error-suppression factor of
only Λ≈1.56, well below the Λ≈2.14 AlphaQubit
reaches on the same data [1, 2]. Closing that gap is
not the only requirement, however: whichever decoder
is used must also stay fast enough to keep pace with the
rate at which syndromes are measured, around 1µs for
superconducting qubits [2, 6].
Machine learning-based decoders have developed from
solving toy decoding problems [7–16] to learning the noise
model directly from experimental data [17–19]. The state
of the art is AlphaQubit, a recurrent transformer that
outperformed any classical decoder on Google’s surface
code memory experiments [1] and has since been scaled

to larger codes with real-time throughput [20]. Parallel
work has focused on low-latency architectures and hard-
ware integration [19, 21–26]. The crucial question we
address in this work is whether a neural decoder can per-
form well on real dataportably: across hardware plat-
forms, noise profiles, and different amounts of available
data, and across logical operations beyond the standard
memory experiment, all without re-engineering the de-
coder for each setting.
In response to this challenge we introduce a mod-
ular neural decoder. The architecture, which ex-
tends our earlier graph-neural-network decoder [18] and
the hybrid graph-recurrent model of Ref. [27], follows
a renormalization-group-inspired design [28]: a single
learned encoder, processing a 3×3×2 space-time block
of detection events, is reused at every scale, its per-block
embeddings coarse-grained by a small convolutional layer
and integrated over time by a recurrent network. Each
new code distance, or adjacent surface code patches dur-
ing lattice surgery, adds only a small convolutional ag-
gregation module, so the parameter count is essentially
independent ofd; nearly every model in this paper con-
tains a few million parameters and was trained on a single
GPU.

II. SURFACE CODE BACKGROUND:
MEMORY, STABILITY, AND LATTICE
SURGERY EXPERIMENTS
The surface code encodes one logical qubit in a two-
dimensional lattice ofdataandmeasurequbits [3, 4].
Data qubits sit on the lattice vertices; measure qubits,
one per plaquette, repeatedly measure four-qubit (or, at
the boundary, two-qubit)X- orZ-type stabilizers ar-
ranged in a checkerboard, so that every bulk data qubit
participates in twoX-type and twoZ-type stabilizers.
A stabilizer outcome that differs from its value in the
previous round is adetection event, and it is from the
pattern of detection events accumulated over many sta-
bilizer measurement rounds that a decoder infers whether
a logical observable has been flipped. Which logical ob-
servable(s) can be defined in a given experiment depends
on the boundary conditions, as well as initialization and
measurement bases, as we describe next.
A. Memory versus stability experiments
A conventional surface code patch has two pairs of
boundaries of opposite type, e.g.Z-type top and bot-
tom andX-type left and right, so that a logicalZ L
(XL) operator can terminate on the twoZ-type (X-type)
boundaries (Fig. 1(a)). Thememory experimentinitial-
izes and measures the data qubits in one basis, sayZ, and
asks whether the corresponding logical observableZ L is
preserved through multiple rounds of stabilizer measure-
ments with data, measurement, and gate errors. In the
spacetime picture the patch is a tube whose temporal

III. DECODER ARCHITECTURE AND
TRAINING PIPELINE
A. Base decoder
The base decoder is a standaloned= 3 graph-recurrent
decoder (GNN-RNN). On its own, it operates onsyn-
drome graphs[18]: each detection event within a slid-
ing temporal window of size ∆t= 2 becomes a node
annotated with its space-time coordinates. The nodes
are connected all-to-all, with edge weights decaying as
the inverse square of the supremum-norm distance be-
tween their space-time coordinates, resembling the decay
in probability of chains of i.i.d. error events with increas-
ing length. A message-passing GNNencodeseach win-
dow’s graph into a fixed-length vector; windows without
detection events contribute a learned “empty” embed-
ding. The sequence of window embeddings is processed
by a multi-layer gated recurrent unit (GRU), and a linear
head maps the output to the probability that the logical
observable flipped (which observable depends on the ex-
periment, Sec. II). Because the GNN acts on individual
windows and the GRU carries all temporal context, the
decoder generalizes to experiment durations far beyond
those seen in training; we train att= 50 rounds and
evaluate up tot= 1000 (Appendix A 1).
B. Modular decoder
In the bulk of the surface code lattice, every stabi-
lizer has the same neighborhood structure up to trans-
lation. This permits a renormalization-style decomposi-
tion [28]: a distance-(2k−1) code splits into four over-
lapping distance-ktiles that share boundary stabiliz-
ers along their seams, each of which closely resembles
(though, due to boundary effects from sitting inside the
larger lattice, is not exactly identical to) the structure of
a standalone distance-kcode. Each tile is processed inde-
pendently, and the results are combined into an effective
description one level up. Ford= 5, we achieve this by
running thesameGNN encoder of the pretrainedd= 3
decoder on every tile and coarse-graining the four tile
encodings with a 2×2 convolution, whose output feeds
the GRU and prediction head (Fig. 2(a)). This recursion
extends tod= 9 by nesting: fourd= 5 modules feed a
d= 9 module, and so on (Fig. 2(b)).d= 7 does not fit
the 2k−1 recursion; instead, nined= 3 tiles cover the
code on a 3×3 grid, sharing seam stabilizers along tile
boundaries the same way, aggregated by a 3×3 convo-
lution, see Appendix B for details.
A standaloned= 3 decoder has≈1.6 million pa-
rameters. Composing it into a larger decoder reuses this
entire base decoder, GNN encoder and GRU alike (with
its weights continuing to update during composite train-
ing), and adds only one small convolutional aggregation
module per additional level (≈0.3 million parameters per
2×2 aggregation used atd= 5,9;≈0.66 million for the
3×3 aggregation used atd= 7). The resulting parameter
count is therefore nearly independent ofd:≈1.9 million
atd= 5,≈2.3 million atd= 7 andd= 9, small enough
that every model in this paper, up tod= 9 on simulated
andd= 7 on real data, was trained in at most a few days
on a single GPU. The one exception is a wider variant of
thed= 7 decoder, with the GRU hidden size raised from
256 to 1024 (≈30 million parameters), which we use in
Sec. IV A 2 to test how accuracy at largerddepends on
the capacity of the recurrent state.
Nothing in the base decoder is specific to the mem-
ory experiment. Its input, the sequence of per-window
syndrome graphs, is built identically from the detection
events of any surface code circuit, and the choice of exper-
iment in Sec. II enters only through (i) the binary label
that the linear head is trained to predict and (ii) the spa-
tial layout of the surface code patches that the modular
decoder tiles. For the memory experiment (Fig. 1(a,b))
the label is the flip of the tracked logical operatorZ L
between initialization and final measurement. For the
stability experiment (Fig. 1(c,d)) the patch differs from
ad= 3 memory patch: withX-type boundaries on all
four sides it has a different shape and a different number
and arrangement ofX- andZ-type stabilizers (compare
the stability and memory patches in Fig. 3). Because the
GNN acts on graphs of detection events labeled by their
space-time coordinates rather than on a fixed stabilizer
grid, the base decoder architecture nevertheless applies

C. Three-stage fine-tuning pipeline
All hardware results use the following training
pipeline [1]:
Stage 1 — synthetic pretraining.The decoder is
trained on Stim-simulated circuits [43], either circuit-
level depolarizing noise (p∈ {0.001, . . . ,0.005}) or a
superconducting-inspired SI1000 noise model [44] with
error rates scaled to match the target device’s observed
detection-event density.
Stage 2 — calibrated error model.From the de-
vice’s real detection events we fit correlation probabili-
tiesp i1i2...ik up to orderk= 4 and build a detector error
model [45–47]. The decoder is fine-tuned on synthetic
samples generated from this model [1].
Stage 3 — real data.Finally the decoder is fine-tuned
directly on the recorded hardware detection events, split
80/10/10 into train, validation, and a held-out test set
from which all reported numbers derive. Appendix C
shows how much of this validation accuracy is reached
during each stage. All syndrome extraction cycle counts
are mixed within every optimizer step, which preserves
the temporal generalization of the base model.

IV. RESULTS
A. Memory experiments
1. IBM hardware
Previous QEC experiments on IBM hardware used ear-
lier device generations [47, 49–53]; surface code mem-
ory and stability experiments [54, 55] as well as lat-
tice surgery [56] were recently run on the square-lattice
Nighthawk r1 generation. We ran three surface code
memory experiments on the IBM Nighthawk r1 proces-
soribm berlin: two independentd= 3 regions and one
d= 5 region. Fig. 3 shows the physical placement of three
of the four hardware patches (each patch labeled by the
physical index of its center data qubit under the chip’s
row-major numbering): thed= 5 memory patch (q85),
the independentd= 3 memory patch (q36), and the
d= 3 stability patch (q85) used for the stability experi-
ment of Fig. 6. The fourth, thed= 3 memory patch that
is thed= 5 patch’s inner core (also centered on q85), is
omitted from the figure for clarity. Two constraints lim-
ited where a patch could sit. First, on this device gener-
ation, qubits with odd row+column parity suffer vastly
degraded mid-circuit readout, so every measure qubit in a
viable patch must have even row+column. Second, dead
and degraded couplers on this device (dashed purple lines
in Fig. 3) ruled out most candidate regions. Therefore the
region that remains large enough to host a 5×5 patch
with even-parity measure qubits free of those defects is
pinned against the edge of the chip. We resolved the
corner constraint using the defect-adaptation approach
of Ref. [57] (see Ref. [54] for a comparison of defect-
handling strategies on the same processor generation):
we removed the corner data qubit and its neighboring
boundary measure qubit, leaving the adjacent boundary
measure qubit q115 at weight 3 instead of weight 4. This
reduces the code distance for the logicalXobservable to
four, while leaving the complementary logical observable
(Z, the basis used for the memory-experiment results of
Table II) at the full distance of five.
Mid-circuit reset is slow on this device, so we use a
scheme where measure qubits are measured but never re-
set between rounds. We recover the standard per-round
detection event by comparing outcomes two rounds
apart [58]. With 10 5 shots at each durationt∈
{5,10,20,30,50}, we applied the pipeline of Sec. III C:
Stage 1 pretrains on SI1000 circuits with noise scaled to
each patch’s detection-event density, Stages 2 and 3 fine-
tune on the patch’s calibrated detector error model and
real detection events, respectively.

V. DISCUSSION
The combined results establish the versatility of our
modular neural decoder: the same basic architecture,
using a convolution over local GNN encoders together
with a recurrent temporal unit, and the same three-
stage training pipeline, produce MWPM-beating decod-
ing on two hardware platforms and on three different
logical-observable experiments. Neural decoders trained
on experimental data have mostly been demonstrated
on surface code memory experiments [1, 17, 19, 20],
and only recently on logical operations such as lattice
surgery [40, 42], typically with a decoder trained for each
experimental configuration. Here, the components them-
selves are reused: a single local syndrome encoder, pre-
trained ond= 3 patches, is shared across memory, sta-
bility and merge experiments, and each new experiment
changes only the training label and a small aggregation
layer, while the training pipeline stays the same.
Neural decoders are currently being developed with
different priorities: large models such as AlphaQubit [1,
20] reach the highest accuracies on experimental data,
while compact networks target the microsecond latencies
of real-time decoding [21, 23–26], and it has been argued
that near-term accuracy depends more on the amount
of training data than on architectural complexity [59].
With a few million parameters and single-GPU training,
our decoder is small enough that the full pipeline can
be rerun for every patch, experiment type and noise set-
ting, which is what made the stability sweep and the

The Google results (Sec. IV A 2) suggest that recurrent
capacity becomes increasingly important at larger code
distances. A natural next step is to give each tile its own
recurrent state ahead of the spatial aggregation, so that
capacity grows with the number of tiles while the mod-
ular structure and the reuse of the pretrainedd= 3 en-
coder are kept; related local, weight-shared designs have
been explored in AlphaQubit 2 [20] and in convolutional
decoders [9]. Seed ensembling and larger pretraining sets

Our Google results cover theZbasis; training theX
basis is straightforward but not yet done. IBM results
stop atd= 5, set by the currently available patch qual-

shows that thed= 5 patch is noisier than thed= 3
core it contains, so error suppression with distance on
IBM hardware awaits better devices, not a different de-
coder. We report no latency or throughput benchmarks.
The per-round cost of the architecture is constant in ex-
periment duration, which is compatible with, but does
not by itself demonstrate, real-time operation. Real-time
neural decoding has meanwhile been demonstrated on
TPUs [19, 20] and FPGAs [26]. For our GNN, we have
previously shown sub-microsecond decoding per round
on an FPGA for a fixed time window [25]; extending this
to streaming multi-round syndrome data is the natural
next step.
VI. CONCLUSION
We have presented a versatile modular neural decoder
which has been applied to a range of surface code exper-
iments, including memory, stability, and lattice surgery,
as demonstrated through experiments on superconduct-
ing quantum hardware. Logical accuracies in all three in-
stances match or outperform those of a hardware-noise-
informed matching decoder. The modular structure of
the decoder makes it readily adaptable to any near-term
surface code experiment. The moderate size of the neu-
ral network implies that the required training compute is
manageable on a single GPU and can facilitate portabil-
ity to hardware systems dedicated to decoding streaming
data. The decoder is purely data-driven and does not re-
quire the decoding problem to admit a matching formu-
lation, making it applicable in principle to a broader class
of quantum error-correcting codes. Future work should
explore this potential beyond the surface code and ex-
tend the approach to the larger code sizes expected on
next-generation quantum hardware.
