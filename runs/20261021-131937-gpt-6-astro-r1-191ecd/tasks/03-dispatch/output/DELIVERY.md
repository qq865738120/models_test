# 鹈鹕配送 · 调度工作台

已交付五个独立页面：订单派送、运营总览、配送员、运行报表、工作台设置。采用 React + TypeScript，所有订单查询、详情、统计、配送员及派单均调用真实 HTTP 接口。

## 启动与归档

- 前端入口：`index.html`，资源位于 `assets/`，均为本地相对路径。
- 后端入口：`server/index.mjs`；仅使用 Node 内置模块，无需安装依赖。
- 在本目录运行 `PORT=4174 node server/index.mjs`，或将 PORT 替换为主持人分配的独立端口。仅监听 `127.0.0.1`。
- 前端由工作台静态预览代理提供，并将相对 `api/…` 请求转发至本成果的后端；后端本身不承担静态文件托管。
- 固定种子：`server/data/orders.json`，与原材料逐字节一致。浏览器不读取种子；业务状态仅保存在 Node 进程内存，刷新页面保留派单，重启服务恢复种子。
- 页大小仅保存在 React 内存，刷新恢复 20 条；不使用浏览器持久存储、外网资源、外部服务或其他项目状态。
- 本地自测因默认端口已被占用，使用本题 `.runtime/preview.mjs` 启动独立随机端口的归档后端，并在 `127.0.0.1:48173` 提供本地测试代理。交付不依赖这个测试代理。

## 已实际验证

`npm run build` 已完成 TypeScript 检查、生产前端打包和后端/固定种子打包。

通过 `node solution/api-test.mjs` 在归档目录启动独立服务，完成 9 组 HTTP 断言，结果记录见 `verification/api-results.json`：

- 健康检查、三名配送员、初始统计与动态快照时间。
- 默认/末页/超范围分页、完整详情；编号、客户、地址搜索及状态组合筛选。
- 参数空值、范围、重复、未知键、非法编码、方法与未知资源的错误码。
- 派单字段与类型、空/重复/超过 100 个 ID、无效配送员、JSON、Content-Type、64 KiB 限制。
- 未知订单优先返回 404；非待派状态返回 409；失败不修改任何一单。
- 100 单提交、请求顺序、仅改变 status/courierId、独立 HTTP 客户端共享数据。
- 重叠并发批次一个成功、一个冲突，落败批次其他订单不变；重启恢复初始 10,000 条种子。

使用本地 Chromium 浏览器操作了以下流程：

- 搜索、空结果恢复、四状态筛选、混合状态全选、翻页清选择、末页禁用、普通菜单切换保留查询和页码。
- 配送员快捷入口预选、无配送员时禁止确认、取消保留勾选；代理制造派单 503 后重试成功；提交期间按钮禁用，Esc 不误关闭。
- 独立客户端抢先派单造成 409，页面保留失败上下文并提供刷新重选；批次内另一订单保持 pending。
- 详情字段、优先级、备注占位及真实备注；列表/详情/报表错误重试。
- 慢 A 后快 B：分别测试旧成功和旧失败，B 的结果保持不被覆盖。
- 派单后详情、总览、报表同步；浏览器刷新保留派单；重启本题服务后恢复种子。
- 20/50/100 条设置、未保存不生效、保存返回第一页、页面刷新恢复 20 条。
- Esc 关闭详情后焦点回到入口；派单完成后焦点进入搜索框；原生模态 dialog 阻止背景操作。
- 1440×900：实测侧栏 220px、顶栏 72px、内容内边距 32px、行高 56px。
- 390×844：导航、筛选、派单、详情、设置及五页布局检查，整页宽度为 390px，订单表格在卡片内部横向滚动。

## 输入性能实测

在生产构建中加载原始 `tools/performance.js`，1440×900、DPR1，预热 10 秒，每组 30 次输入，间隔 500ms：

| 当前页数量 | 输入反馈 P95 | 实际渲染订单行 |
| --- | --- | --- |
| 20 条 | 1.5ms | 20 |
| 100 条 | 5.3ms | 100 |

原始样本与浏览器信息见 `verification/performance-20.json` 和 `verification/performance-100.json`。此结果为公开采样器定义的下一次绘制机会近似值，不包含接口等待；同时核对了输入框可见值与预期值一致。
