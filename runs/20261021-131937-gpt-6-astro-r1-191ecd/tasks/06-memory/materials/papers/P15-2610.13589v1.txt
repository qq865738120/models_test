Decoder- and Noise-Aware Optimization Framework for Clifford-Deformed Quantum
Error-Correcting Codes
Julius Rye Bønnelykke ,∗ Benjamin Joecker , Peter Krogstrup ,
Vincent Philippe Michal ,† and Mark Kamper Svendsen ‡
NNF Quantum Computing Programme, Niels Bohr Institute,

Practical fault-tolerant quantum computing requires qubit-efficient quantum error correction
(QEC). Clifford deformations (CDs) modify the stabilizers of a QEC code to lower its logical er-
ror rate at no additional resource cost. However, the number of possible CDs grows exponentially
with the number of qubits, making exhaustive search infeasible beyond small codes. In this work,
we further show that under circuit level noise the optimal CD depends strongly on both the noise
model and decoder. To make systematic CD optimization possible, we introduce Evolution-Based
Best-arm Identification (EBBI), a shot-efficient search algorithm that treats the circuit, noise model
and decoder as a black box. We benchmark EBBI’s performance on the rotated surface code, under
two stronglyZ-biased circuit-level noise models with the PyMatching decoder. At distance 3, EBBI
finds the optimal CD using up to∼1100×fewer shots than random search. At distance 5, when
run at the target error rate, the median EBBI run converges to the CDs we believe to be optimal,
while random search never converges. Under aZ-biased SI1000-like noise model, EBBI discovers
a new CD, the B-XZZX code, which we generalized to larger distances. It differs from XZZX on
only a fractionO(d −1) of the qubits at code distanced, yet its relative advantage grows from≈5%
atd= 3 to≈12% atd= 11. We thus show that the B-XZZX pattern found by EBBI can be
systematically scaled to larger code distances. Our work represents a first step towards scalable CD
optimization for general QEC codes.
I. INTRODUCTION
Quantum error correction (QEC) is widely regarded
as the leading route toward fault-tolerant quantum
computation [1–3], and finding efficient QEC schemes
is at the forefront of current research [4–6]. There exist
QEC codes with a range of performances and demands
on hardware. Among them, the most well-known and
widely used is the surface code [7–12]. The surface code
encodes a single logical qubit into a two-dimensional code
patch with code distancedconsisting ofO(d 2) physical
qubits, representing a considerable overhead in physical
hardware. More recently, efficient high-rate quantum
low-density parity-check (qLDPC) codes [13–15] have
attracted attention for their ability to encode many
logical qubits (possibly with constant encoding rate)
within a code, although with the additional requirement
of long-range connections, realized either in hardware or
by algorithmic routing [16–18]. The above-mentioned
codes rely on implementing stabilizer circuits [19] from
which errors on qubits may be detected and corrected.
Beyond the development of new QEC codes, the per-
formance of a QEC implementation can be improved sys-
tematically at a fixed code layout by exploiting the struc-
ture of the noise and errors affecting the individual phys-
ical qubits [20]. Modifications of the surface code stabi-

error channels and optimize code performance without
increasing qubit overhead [21, 22]. This was later gen-
eralized to the concept of Clifford deformations (CDs)
in the context of the surface code [23], and then applied
to a family of high-rate qLDPC codes [24]. Structure in
the errors affecting qubits is relevant to a range of ex-
perimental platforms, including qubits realized by super-
conducting circuits [25, 26], spin qubits in semiconductor
quantum dots [27], spins of defects in silicon [28], neutral
atoms [29], and trapped ions [30].
Previous approaches to CD optimization fall into four
categories: analytical constructions for a specific code
family [21, 22]; local rules that set the deformation of
each qubit from its dominant error axis [31]; exhaus-
tive search on the distance-3 rotated surface code (re-
ferred to as the surface code for the rest of this pa-
per) combined with a study of random CD families,
from which a translation-invariant CD for larger codes
is constructed [23]; and fast optimization of a decoder-
independent surrogate for CD performance under spa-
tially non-uniform noise [32]. Specific CDs such as
XZZX and XY have been studied under circuit-level
noise [26, 33, 34], but searches for optimal CDs have
so far been carried out under code-capacity noise with
near-optimal decoding [23] or under phenomenological
noise with an objective that ignores the decoder [32], with
only a limited circuit-level test in the latter. Exhaustive
search with the decoder in the loop accounts for the de-
coder by construction, but its cost grows exponentially
with the number of qubits, while the scalable alternatives
(local rules, random-family analysis and surrogates) are

Here, we introduce Evolution-Based Best-arm Iden-

The key observation underlying EBBI is that small
changes to the CD patterns produce similar logical
error ratesP L. This allows information gathered from
one configuration to guide the search toward promising
regions of the exponentially large configuration space.
We evaluate EBBI using realistic circuit-level noise
models suitable for a range ofZ-biased qubits [34] and
practical decoding based on PyMatching [35]. Across a
range of surface-code instances under circuit-level noise,
EBBI consistently identifies CDs that either match or
outperform previously proposed constructions under the
considered noise models and decoding strategies while
requiring several orders of magnitude fewer QEC eval-
uations than random search. In particular, the search
strategy allowed us to identify code boundary effects
for ourZ-biased SI1000-like noise-model [Sec. IV A] not
reported so far [Sec. IV C]. These boundary effects turn
out to be relevant at large code distances, as scaling up
the code while maintaining the structure found at low
distance consistently outperforms previously identified
codes at larger distances. Our results establish a
scalable CD optimization as a practical tool for tailoring
quantum error-correcting codes to hardware-specific
noise characteristics.
The structure of this paper is as follows. In Section II
we recall the method of CD of a QEC codes. In Sec-
tion III we describe the EBBI algorithm as applied to the
CD of QEC codes. Then, we present in Section IV the
optimal CD found with the EBBI framework, benchmark
the algorithm’s performance, and show how the method
can be extended to large codes based on codes discov-
ered at low distance. We discuss and give an outlook in
Section V.

III. EVOLUTION-BASED BEST-ARM
IDENTIFICATION
EBBI aims to identify the optimal CD for an arbitrary
Pauli-stabilized QEC code, biased noise model, and
decoder using as few simulations as possible. EBBI
is a hybrid between a best-arm identification [36]
algorithm and an evolutionary algorithm, as best-arm
identification usually assumes a small, limited set of
options, which is not the case here. The advantage of
EBBI is that it obtains all information about the circuit
implementation, noise model, and decoder assumptions
through simulation steps. This allows it to work with
any decoder, including those whose underlying assump-
tions are not known, as would be the case with machine
learning decoders. Below we outline the three steps
EBBI goes through:initialization,sampling, andprune
and re-populate.
InitializationAn active Clifford-deformation setAis
selected. This could be the full setA 6, the reduced set
A3, or some other subset ofA 6; the search space is then
An. EBBI uniformly samplesKrandom CDs fromA n
as candidates. Each candidate CD undergoes a warm-
up phase, in which simulations are run untilWlogi-
cal faults have been observed. The trueP L of the CD
is modeled as a beta distribution with parametersα=
#LogicalFaults + 1 andβ= #SuccessfulDecodings + 1
[Fig. 1b].

the candidatesP L. EBBI selects the candidate distribu-

of 1.5, requiringS·(1.5 2 −1) = 1.25Sadditional shots,
whereS=α+β−2 is the number of shots already used
on the candidate CD [Fig. 1c]. The factor of 1.5 is a hy-
perparameter of the model that can be fine-tuned: too
small a value would trigger the simulation step too of-

IV. RESULTS
A. Setup
While EBBI will work for any stabilizer code, we here
limit our focus to the surface code. This is done for
two reasons: (1) Several CDs of the surface code are al-
ready known, including the XZZX [22] and XY [21] CD,
and it is the code that was studied in Ref. [23], which
introduced the generalization of CDs. (2) The surface
code has only a single logical qubit, meaning that per-
formance improvement can be uniquely measured by the
single logical qubitP L. This is unlike codes with multi-
ple logical qubits co-encoded in the same physical qubits
where tradeoffs between the different encoded qubitsP L
might need to be considered.

level biased noise model. The Stim circuits are compiled
down to single-qubit rotations, CZ gates, and initializa-
tion and measurement in the Z-basis [Appendix C]. The
reportedP L is determined from simulating and decoding
the same circuit in both the X- and Z-basis under the
same noise seed (circuit-level errors will be the exact same
in both runs) and comparing the two results to determine
which logical Pauli error occurred, giving usP I

B. Performance
Across all cases tested (each case is the medianP L
over 25 independent runs), EBBI shows a significant
speedup over random search. For the distance-3 sur-
face code, EBBI finds the optimal CD in almost all
cases [Table IV in Appendix G] (confirmed by an ex-
haustive search over all 3 9 A3-CDs [Appendix E]). Un-
derp search =p= 0.1% and HBD noise, the median EBBI
run reaches the optimum using∼450×fewer shots than
random search [Fig. 2a], and∼30×fewer under HBD-
SI1000 [Fig. 2c]. Increasingp search to 0.5% expands this
gap to∼1100×under HBD noise. Under HBD-SI1000
noise withp search ∈ {0.25%,0.5%}, the random search
median never reaches the optimalP L for two reasons: (i)
each random search run samples CDs without replace-
ment and stops once it repeatedly fails to draw a CD it
has not previously used, so in practice each run covers
only≈78% of the 3 9 CDs; and (ii) its per-CDP L esti-
mates are too noisy to resolve the separation between the
optimal and second-best CDs, which is about one stan-
dard deviation of the random search estimate. For the
distance-5 surface code, no random search run converged:
finding the optimum by uniform sampling requires on the
order of 3 25 ≈10 12 CDs, each using 10 7 shots, which is
far beyond our simulation budget. Under HBD noise,
the EBBI median reaches the XZZX deformation for all
threep search settings [Fig. 2b]; we believe it to be optimal,
as no CD explored by EBBI or random search beats it.
Under HBD-SI1000 noise, the best CD found is B-XZZX
[Sec. IV C], but the fraction of runs that end on it drops
withp search: 16 of 25 runs atp search = 0.1%, 6 at 0.25%
and none at 0.5%. Two failure modes contribute. First,
some runs never sample B-XZZX (7, 13 and 23 runs, re-
spectively [Table IV in Appendix G]) and end on a CD
with a higherP L than B-XZZX, also when evaluated at
the elevatedp search, which likely indicates that they are
stuck in a local minimum. Second, some runs do sample
B-XZZX, but end pruning it out at a later stage (2, 6 and
2 runs, respectively [Table IV in Appendix G]). Potential
fixes to these two problems are discussed in Sec. V.
The plots in Fig. 2 clearly show that usingp search > p
can reduce the shot count by 1 to 2 orders of magnitude.
For the distance-3 surface code under HBD noise, increas-
ingp search from 0.1% =pto 0.5% = 5pallows the median
EBBI run to find the optimal CD 10×faster while ran-
dom search finds it 4×faster [Fig. 2a]. Meanwhile, un-
der HBD-SI1000 noise, the gain from increasingp search
is slightly larger for EBBI at about 12×, while the me-
dian random search run fails to identify the optimal CD
under bothp search = 0.25% and 0.5% [Fig. 2c]. For the
distance-5 surface code, the gain increases to close to 80×
for EBBI under HBD noise when increasingp search from
0.1% to 0.5% [Fig. 2b], with random search never con-
verging due to the exponentially large 3 25 space. Under
HBD-SI1000 noise, increasingp search is less successful; at
psearch = 0.25%, EBBI almost converges to the B-XZZX
code while forp search = 0.5% it does not converge at all
to the B-XZZX code. This could either be a result of the
lower Pearson correlation under HBD-SI1000 compared
to HBD, especially in the top 100 CDs, which was seen
in the exhaustive search results for distance-3 [Fig. 7 and
Fig. 8 in Appendix E] or something caused by the prun-
ing logic in EBBI. To test this, we used the B-XZZX
CD found atp search =pand compared itsP L against
that of the final CDs found atp search ∈ {0.25%,0.5%}at
their corresponding noise models and saw that B-XZZX
remains the CD with the lowestP L. This leads us to

C. Generalization to larger codes
A strong dependence between the CD found and the
noise model is observed. In both the distance-3 and
distance-5 instances under HBD noise, the well-known
XZZX CD is rediscovered by EBBI. However, when the
noise model is changed to HBD-SI1000, XZZX is no
longer optimal and a new code, B-XZZX, is discovered,
despite the HBD-SI1000 noise model using the same bias
η= 500 as that of the HBD noise model and differing
only in the relative noise strengths between operations.
The best CD found under the HBD-SI1000 noise model
for the distance-3 and 5 cases [Fig. 2c,d] can be general-
ized to larger surface code distances. It can be viewed as
the XZZX CD [22] with a modified border. All the qubits
on the left and right edges and on the NE and SW cor-
ners use theHdeformation, while the remaining edge
qubits use no deformation [Fig. 3a,b]. This generalized
form differs from the XZZX code on only 2(d−1) qubits
in the distance-dcase. For this reason we will refer to it
as the bordered XZZX code or simply B-XZZX.
Remarkably, despite the B-XZZX code differing from
the XZZX code on only a diminishing fraction 2/d−2/d 2
of the qubits, its relative performance over the XZZX
code increases with code distance [Fig. 3c]. We note
that the improvement over XZZX flattens out between
d= 9 andd= 11 and could potentially decrease after
this point; however, the same thing was observed be-
tweend= 3 andd= 5 making it hard to conclude any-
thing definitively. Atd= 11 theP L under HBD-SI1000
noise withp= 0.1% andη= 500 is∼10 −7 making
it increasingly expensive to test at even larger code dis-
tances. This shows that despite EBBI only being tested
ond= 3 andd= 5 surface codes, it is possible to gener-
alize the CD pattern into a scalable CD that maintains
good performance.

XZZX code under the HBD-SI1000 noise model are a
result of the primarily X-errors left on the data qubits by
the CX gates [Appendix C 1]. Interestingly, the B-XZZX
code prefers having two CX and one CZ gate on the edge
data qubits instead of two CZ and one CX; this choice re-
sults in a more even distribution of X and Z errors on the
edge data qubits—the gate choice mainly contribute X-
errors, while idling of the data qubits during check-qubit

A different proposal for scaling up found CDs on the
surface code to larger distances is given in Ref. [23]. They

while here we use a circuit-level noise model with a sub-
optimal decoder. This illustrates the non-trivial problem
of generalizing small CDs to larger distances.
V. DISCUSSION AND OUTLOOK
In this work we have ranked the CDs by directly esti-
mating theirP L through circuit-level simulations, which
becomes expensive as the size of the codes increases.
An alternative to this is to construct a cheap surrogate
for the performance of a CD and optimize for that in-
stead ofP L directly. Ref. [32] has done exactly this,
using a decoder-independent surrogate that allows them
to find optimal CDs extremely fast, keeping up with an
ever-changing calibration map. However, under both the
HBD and HBD-SI1000 circuit-level noise models consid-
ered here, the optimal distance-3 surface codeA 3-CD
changes depending on whether the PyMatching or BP-
OSD decoder is used; a Pearson correlation ofρ= 0.88
andρ= 0.30 between the two decoders’P L over allA 3-
CDs is observed for the HBD and HBD-SI1000 noise
models respectively [Fig. 10 in Appendix H]. Thus, to
reliably and quickly find the optimal CD for sub-optimal
real-time decoders, the surrogate will have to incorporate
information about the decoder in addition to information
about the noise model and QEC code.
Boundary modifications similar to the ones we perform
on the XZZX code to get the B-XZZX code have been ap-
plied to the XY code. Ref. [33] noted that while the XY
surface code requiresn=d 2 Z-errors for an undetectable
logical error, if just a single non-Z-error is allowed, an
undetectable logical error can be constructed using only√n−1Z-errors on the boundary of the code. They show
that if a deformation is performed on every other edge
qubit of the code,O( √n) non-Z-errors are required to
achieve the same effect, significantly increasing the per-
formance of the code [Appendix G of Ref. [33]]. However,
we believe that what we are seeing in the B-XZZX code is
something different as both a logical-XandZerror can
be constructed using a single non-Z-error and √n−1Z-
errors. Thus, the increasing performance of the B-XZZX
code over XZZX as the code distancedincreases remains
unexplained.
In Sec. IV B we observed two failure modes of EBBI
for the distance-5 surface code under HBD-SI1000 noise.
First, some runs get stuck in a local minimum. One so-
lution to this is to replace a pruned CD with a uniformly
random CD instead of a mutation once many consecutive
mutations have been pruned. This allows EBBI to escape
local minima, but may add significant overhead, since a
random CD is unlikely to be close to optimal. Second,
some runs discover the optimal CD only to prune it out
at a later stage, a result of overly aggressive pruning.
This happens when a new CD, whoseP L estimate is still
based on few logical errors, appears better than the op-
timal CD by chance, causing the optimal CD to satisfy
Eq. (1). We see three possible solutions. (i) Decreasing
γreduces the rate of such false pruning, at the cost of
more shots per CD. (ii) IncreasingWgives a more ac-
curate initialP L estimate of each new CD, reducing the
risk that it falsely appears better than the optimal CD.
(iii) A previously pruned CD could be re-added, in place

For device-level application of EBBI, a per-qubit cal-
ibration map of theZ-bias and of the relative noise
strengths between operations and qubits is needed.
While the two noise models considered in this work, HBD
and HBD-SI1000, are both uniform noise models, the
power of EBBI comes from its use of the strongP L cor-
relations between similar CDs. We do not expect that
going from a noise model where all qubits are identical
to a per-qubit noise model will have any significant ef-
fect on this correlation and thus expect that EBBI will
continue to perform well under per-qubit noise models
calibrated from real devices.
While we already see that EBBI performs well, there
are several things that might improve its performance
even further.Pruning:The way the pruning step cur-

added back in at a later point; we have tried remov-

convergence. It would be interesting to explore the pos-

out to be re-added under certain conditions.Mutation:

VI. CONCLUSION
In this work, we have introduced EBBI, a scalable
optimization framework for identifying high-performing
Clifford-deformed QEC codes under general physical
noise models and decoders. We evaluated the framework
using realistic circuit-level noise models suitable for a va-
riety of qubit types and practical decoding based on the
minimum weight perfect matching algorithm. With the
surface code as an example case, EBBI identifies CDs
overlooked so far where code boundaries are relevant even
at large code distances. Looking ahead, our results es-
tablish a CD optimization as a practical tool for tailor-
ing quantum error-correcting codes to hardware-specific
noise characteristics that is broadly applicable to various
stabilizer codes, decoders, and quantum computer archi-
tectures.

Appendix C: Circuit construction
Circuit construction can be viewed in three levels.
(1) The circuit is constructed using all three two-qubit
controlled gates (CX, CY and CZ) and check qubits
are initialized and measured in the X-basis. This is
the most direct construction from the code schematics
[Fig. 1a, Fig. 4a left]. (2) Measurement and initializa-
tion can be compiled to the Z-basis usingHgates and
the CX and CY gates can be constructed withCX=
(I⊗H)CZ(I⊗H) andCY= (I⊗H Y Z)CZ(I⊗H Y Z)
[Fig. 4a right]. (3) Finally, the single-qubit gatesHand
HY Z, along with their productsHH Y Z andH Y Z Hcan
be Euler decomposed into aZ−X−Zrotation [Fig. 4b].
The twoZrotations are usually handled in the control
software without requiring any signals to be sent to the
quantum chip, making them instantaneous and error free.

For this reason, theH,H Y Z,HH Y Z, andH Y Z Hcan all
be viewed as a singleπ/2 X-rotation and be given the
exact same single-qubit depolarization error channel.
1. Bias of CX and CY gates
This choice of compilation of CX and CY gates us-
ing single-qubit rotations and CZ gates leads to a bias
on the CX and CY gates. Going from our noise model
[Table I, Appendix B], the CZ gates primarily produce
Z-errors on both target and control qubits under high
biasη≫1. The control qubit (check qubit in the case
of QEC) remains unmodified, maintaining a dominant
Z-error term, while the target qubits (data qubits) trans-
form the Z-error intoX-errors (Y-errors) after the ap-
plication ofH(H Y Z) gates for CX (CY) gate. If the
single-qubit rotations have low error rates, which is the
case under the HBD-SI1000 noise model, the target qubit
(data qubit) will be heavily biased in theX(Y) direc-
tion for the CX (CY) gate. However, under the HBD
noise model where the noise strength of the single-qubit
operations is the same as that of the two-qubit CZ gate,
this effect is washed out due to the large depolarization
channel.

a similar thing is going on. As for the data idling er-
rors, the argument used in the code-capacity noise model
carries over directly. TheX-errors on initialization and
measurements remain unaffected by the CD as they com-
mute with theCZgates (after being turned intoZ-errors
by theHgates on the check qubits) and result in a classi-
cal readout error, just like in the phenomenological noise
model case.
As for the errors that occur during the stabilizer mea-
surement: The
√
ZswapsCXandCYtwo-qubit gates,
which after circuit compilation [Appendix C] leads to
swapping theHandH Y Z single-qubit gates; leaving the
gate count and ordering unchanged. Both the HBD and
HBD-SI1000 noise models apply DEP errors on both of
these gates, which from itsp X =p Y =p Z symmetry
leaves the detector error model unchanged. The only
non-uniform noise channel occurs after theCZgate,
which primarily producesZerrors that will change into
XorYafter theHorH Y Z gates respectively, depend-
ing on whether a
√
Zdeformation was applied. However,
this has no net effect on the detector error model as the
commutation relations with the other detectors in the
code are unchanged (any stabilizer acting on the given
data qubit is transformed the same way as the error, so
whether they commute is unchanged). As a result, apply-
ing a
√
Zdeformation on any data qubit in the code will
have no net effect on the detector error model and thus
not changeP L, independent of which decoder is used.
To confirm that this holds in practice, Stim detec-
tor error models have been compared. Two circuits
are created; the first circuit uses a random uniformly
drawn CD fromA n

CD by applying
√
Zto a subset of the qubits at ran-
dom. The detector error models from the two circuits are
then compared using Stim’sdem1.approx equals(dem2,
atol=1e-15). This was done on both the distance-3 and
distance-5 surface codes, 1000 times each, under either
HBD or HBD-SI1000 noise and in both the logical X and
Z-basis. An exact match in the detector error models was
observed for all cases used in this paper, confirming em-
pirically the validity of using EBBI on theA 3 set instead
of the fullA 6 set.

Appendix F: Random Search
Random search chooses uniformly random CDs of the
QEC code and samples each a fixed number of times to
estimate theirP L. Random search keeps track of only
the CD with the lowest estimatedP L. It is initialized
with a fixed shot budgetBalong with how many shots
SCD to spend per CD, meaning it will sampleB/S CD

grow exponentially to keep up; (2) as the code distance
dincreases,P L decreases, increasing the number of re-

which CD is optimal, we compare PyMatching decoding
