# 一万只鹈鹕的派单后台

提示词版本：pelican-prompts-4。本阶段预算：25分钟。

使用所附 React + TypeScript 起始工程，制作可实际操作的《一万只鹈鹕的派单后台》。预算25分钟，交付具有五个完整页面、统一设计和真实业务闭环的后台。页面既要功能完整，也要美观、清晰、像可日常使用的业务产品。辅助页面保持轻量，不增加登录、真实后台、配送员增删改或材料不支持的业务。

## 材料与边界
先阅读 materials/START.md、materials/API.md，查看 public/materials/reference.svg。固定10,000条订单和浏览器内Mock已提供。使用 public/materials/mock-api.js 的 createMockApi()，同一应用实例共享一个Mock实例，五个页面切换时不得重新创建或重置订单；不同浏览器页面实例之间独立；生产页面从相对路径 materials/mock-api.js 引入。查询、筛选、分页、详情与派单必须经过该实例，不另造数据源，不连接固定端口服务。控制接口仅用于自测，不在正常业务中绕过错误或重置数据。


## 页面清单与信息架构
必须实现以下五个可通过导航切换的内容页；可以是单个React应用内的视图，不要求五份HTML或安装路由库。默认进入“订单派送”。共享品牌侧栏、顶栏、当前页标题、简短说明和内容区，当前导航项高亮。五个菜单均能进入有实际内容的页面，不能全部跳到同一张表、只更换标题、链接无响应或显示“建设中”。

### 1. 总览
展示全部订单、待派单、配送中、已送达四张统计卡，另有一张订单状态分布图及对应数量/占比文字。点击待派单卡或“去派单”按钮进入订单派送页，设置pending筛选、回到第一页并清空选择。允许复用运行报表的图表组件；不要求额外趋势图或地图。
统计必须来自当前Mock状态：依次取四种status值all、pending、assigned、delivered，调用api.query({status,page:1,pageSize:1})读取各自total（请求可并行）；其他字段使用默认值，统计不随订单页的搜索词变化。百分比分母是全部订单数，分母为0时显示0或“暂无数据”。四项使用同一批请求结果，不混用新旧数值。派单成功后让统计失效并在下次显示前刷新；不要求定时轮询，不扫描100页订单，不把参考图示例值写死。统计请求也有加载、失败与重试状态，尚未拿到数据不能显示为真实0。

### 2. 订单派送（核心工作页）
按reference.svg组织：页面标题和说明、四张共用统计卡、搜索/状态筛选/批量派单工具栏、订单表格、底部分页。表格至少含当前页选择框、订单编号、客户、配送地址、状态、配送员、详情操作；地址过长应合理省略并能在详情中完整阅读。状态使用中文标签，区分pending/assigned/delivered；未分配配送员显示“未分配”。默认每页20条，显示当前页、总条数和总页数，边界翻页按钮禁用。只渲染当前页记录。
详情使用右侧抽屉，手机可改成全屏面板；显示订单编号、客户、完整地址、状态、配送员、优先级、创建时间、contents物品和note备注。无备注显示“暂无备注”，无配送员显示“未分配”。抽屉有独立加载、读取失败与重试、明确关闭入口。
批量派单打开确认对话框，显示已选订单数、配送员选择和取消/确认按钮；未选择配送员时确认不可用。取消不改订单、保留当前选择；确认期间避免重复提交，失败保留可重试上下文，成功关闭对话框、清空已选订单并同步列表/详情/统计。不能把点击批量派单直接做成无对象选择的成功提示。

### 3. 配送员
以三张卡片或紧凑列表展示P01/P02/P03及对应“鹈鹕一号/二号/三号”，说明其用途为选择派单对象。每人提供“为TA派单”，进入订单派送的待派单列表并预选该配送员，仍需用户选订单及确认才能提交。不要求按配送员过滤订单。现有接口没有在线状态、联系电话、运力或个人绩效，因此不虚构这些字段或假排名，不制作无作用的编辑/删除按钮。

### 4. 运行报表
展示当前订单快照的状态数量、占比和一张条形图或环形图，标注“本次页面会话的当前状态快照”及最近成功读取时间；与总览共用真实统计及失败处理。提供“刷新统计”，保持原数据显示或明确加载，失败时说明失败且不伪造最新时间。不要求导出报表，也不要求收入、准时率、配送耗时或历史趋势：材料没有对应事件和时间序列，不能用随机数字、硬编码增长率装饰页面。

### 5. 设置
提供“订单每页条数”20/50/100选项、保存按钮、恢复默认按钮，展示当前生效值。保存后作用于订单页，回第一页并清空已选；恢复默认只把页大小恢复为20，不重置订单、不撤销已经成功的派单。另有简明使用说明，解释数据在内存中、刷新整个应用会恢复初始订单及默认设置。设置只存于当前应用内存，不依赖浏览器持久存储；页面切换保留已保存设置，未保存编辑不影响订单页。返回订单页的入口应可达。

## 页面之间的状态约定
普通菜单切换保留订单页已提交的搜索、状态和页码，但清空已选订单、关闭详情及确认弹层；专用“去派单/为TA派单”入口按上文覆盖筛选。取消/失败不改变业务数据；派单成功后跨页显示一致。不要把每次切页当成刷新整个应用。统计请求与订单列表请求分别管理，过期响应不能覆盖各自最新状态。数据请求仍经过提供的API；用内存视图切换即可，本阶段不额外要求深链接或浏览器历史。

## 完整业务闭环
- 搜索订单编号、客户或地址；支持 all/pending/assigned/delivered 状态；分页展示，默认每页20条。以接口返回的 total 和当前条件计算分页信息。搜索或状态变化回第一页并清空选择；翻页清空选择。
- 选择仅限当前页。只能对 pending 订单派单，已派送及已送达订单不可加入待派批次；提供可理解的全选/取消、已选数量和配送员选择。配送员 P01/P02/P03 与显示名称以 API.md 为准。没有有效选择时不发起派单；提交中避免重复提交。
- 订单详情抽屉展示所点订单的真实完整数据，包括地址、状态、配送员、物品及备注；关闭后返回列表。派单成功后列表、详情和当前选择与Mock状态一致；在“待派单”筛选下，成功派出的订单不应继续当作待派单。
- 请求等待有可见反馈，零结果有空态，错误有明确原因与重试入口。查询条件快速变化时，只能由最新请求更新列表及其加载/错误状态，较早请求的成功或失败不得覆盖新条件。
- 派单整批原子处理。失败后订单数据与Mock原状态一致，显示错误并允许再次操作；若采用乐观更新，失败时恢复数据。不要展示未实际成功的派单结果。

## 视觉、审美与响应式限制
整体呈现克制、清爽的现代业务后台：深色导航、浅灰页面底色、白色内容卡片、蓝色主操作，与reference.svg保持一致。订单页以1440×900为基准：左导航220px、顶栏72px、内容内边距32px、表格行高56px；其他四页沿用同一套布局与视觉语言，可根据内容设计卡片和图表。参考图是核心页的结构和层级依据，不能把它当整张背景图，也不要求订单文字与示例行完全相同。
- 标题、说明、指标数字、正文、辅助文字形成明确层级；系统字体统一，桌面主标题约28px、正文14–16px、辅助信息不小于12px。间距优先使用8px倍数，卡片内边距约20–24px，圆角约8–12px；同类组件在五页保持一致。固定尺寸优先按参考图，窄屏可合理调整。
- 表格列对齐、状态标签可辨、数值与长文本布局稳定；留白服务于阅读，不以大片空白掩盖内容不足。不堆叠浓重阴影、无关渐变、表情符号或大段装饰文案。允许程序化SVG/CSS图表与图标，提供的icon-search.svg可直接使用，不加载外部字体、图片或CDN组件。
- 主操作醒目，每个操作区有明确主次；按钮、导航和输入框具有默认、悬停、焦点、禁用、提交中等适用状态。状态不只靠颜色表达，成功/失败提示含清楚文字；加载、空态、错误态都采用统一样式，不能以闪烁空白或浏览器alert替代正常交互。
- 抽屉/对话框有标题、遮罩、明确关闭或取消入口，不被表格遮挡；键盘可到达控件，打开时焦点进入、关闭后返回触发处，弹层开启期间避免误操作背景。Esc可关闭非提交中的弹层。长内容在弹层内部滚动，按钮可达。
- 390×844下侧栏变为可操作的折叠菜单或紧凑导航，统计卡重排；表格区域允许内部横向滚动，但整页不横向溢出。五个页面及弹层均可用，筛选、分页、派单和设置不被裁掉；触屏主要点击区域不小于40×40px。避免把桌面页面整体缩小到文字不可读。

## 实际验证
逐一打开五个页面，检查内容、导航高亮和返回路径；完成“总览→待派单→选择订单→确认派单→详情→总览/报表数量更新”，以及“配送员预选→派单”和“设置保存50条→返回订单页→恢复默认20条”。检查取消不修改数据、切页不重置成功派单、普通切页保留查询条件。另检查搜索/筛选/翻页后的选择清空、派单失败后重试、空结果、详情读取失败及查询失败。待背景统计请求完成后，针对订单查询通过 api.control 的 delays 制造先发慢查询、后发快查询，确认最终展示后发条件；故障注入后恢复自测环境。记录步骤、预期、实际结果，未执行项目明确标注。
生产构建按 materials/API.md 与 tools/performance.js 统一口径采样：1440×900、DPR1，预热10秒，30次搜索、间隔500ms；输入至可见反馈 P95≤100ms，不含接口等待。采样器测绘制时机近似，需结合实际可见反馈；保存原始采样及环境，不只写“流畅”。整页不得一次渲染10,000条DOM。保留五页桌面截图、详情与确认弹层、手机导航和核心派单流程的可复查记录。提交中说明五页入口和已实现/未实现部分；不能仅展示一张漂亮首屏便声称完成全部页面。

最终入口必须为 `output/index.html`。图片、脚本、样式、数据与物理运行资源全部存于 `output/` 内并使用相对路径引用。页面应能通过普通本地静态HTTP服务打开，也能在iframe中运行；不依赖外网、宿主父页面、固定端口、外部API或额外后端进程。允许使用多个本地资源文件。

# 鹈鹕快递大作战

提示词版本：pelican-prompts-4。本阶段预算：45分钟。

使用所附 Phaser 3 与 JavaScript/TypeScript 起始工程，从空场景制作可实际通关的《鹈鹕快递大作战》。预算45分钟；目标是一张给定关卡的完整游戏，不增加关卡、联网、装备系统或额外美术资产。

## 材料、坐标与引擎
先读 materials/START.md、materials/CONTRACT.md、materials/level.json 和 materials/assets.json。通过 Phaser Scene、GameObject 和物理系统实现主体，不用DOM演出、视频或独立Canvas循环代替。使用 public/materials/ 下同字节布局和统一SVG素材，按契约区分平台左上角、角色/机器人/快递底部中心坐标。不能移动快递、删除障碍或改变公开物理参数来简化通关；不下载或生成额外美术。

## 操作与实体交互
方向键或 A/D 左右移动，空格跳跃，P暂停；手机提供左右和跳跃按钮。只有站在实体平台上才能跳跃，空中不能连续跳。固定平台与往返移动平台均实体碰撞；角色站在移动平台上应随其稳定移动，不穿透、不滑落到平台内部。按布局的速度和端点控制机器人；机器人不阻挡角色，但接触会受伤。角色动画使用提供的待机、行走（8帧/秒）、跳跃及受伤素材，附加反馈可自行设计。

## 一局的规则
- 开始后计时120秒、3点生命。快递重叠拾取，每份只计一次；三份齐全后进入出口胜利，未收齐不能提前通关。
- 接触机器人或危险区扣1点生命，随后0.8秒无敌；持续接触不得每帧扣血，无敌结束后恢复正常受伤。伤害有明显反馈。
- 角色完全离开世界下边界算掉落：扣1点生命并回起点，普通快递收集进度和剩余时间保留。生命耗尽即失败，不再继续游玩；时间耗尽也失败。
- 明确提供开始、游玩、暂停、胜利、失败和重新开始。暂停冻结角色、敌人、移动平台、倒计时及游戏内状态计时；恢复后从暂停处继续。结算后停止移动输入与继续收集。
- 重新开始完整恢复起点、3点生命、120秒、全部快递和所有场景对象；不能累积碰撞回调、敌人或计时器。

## 界面清单与视觉完成度
至少包含开始界面、游玩界面、暂停面板、胜利结算和失败结算五种明确可见的界面状态，可以在同一Phaser场景内切换或覆盖面板。开始界面展示游戏标题、收集三份快递的目标、键盘/触屏操作说明和开始按钮；尚未开始时不消耗倒计时。游玩界面突出关卡和HUD；暂停面板提供继续与重新开始，不能只停画面却没有恢复入口。胜利结算显示送达结果与剩余时间；失败结算说明生命耗尽或超时，并提供重试。
采用统一、明快的2D卡通视觉，沿用所给角色与素材。背景、实体平台、危险物和快递层次分明，不能让装饰被误认为可站立平台；文字与按钮保持清晰对比、尺寸和间距一致，危险与受伤同时有形状/动作或文字反馈。面板不遮挡其必要按钮，不以浏览器alert充当结算，不能用默认调试文字堆砌完整界面。允许用引擎图形或CSS装饰界面，不要求额外绘制或生成美术素材。

## 画面与可玩性
HUD实时显示生命、快递数量和剩余时间。跳跃、收集、受伤、通关均有清晰反馈；显示操作说明及出口条件。镜头随角色移动且不越出关卡。适配1280×720与390×844容器，HUD和触屏按钮可见、不遮住必要操作；允许保持游戏画幅后留白。按下和松开触屏按钮应可靠，不因手指移出按钮而持续移动。

## 实际验证
用真实操作尝试空中连跳、站在移动平台上、持续接触机器人、掉出地图、未收齐进入出口、暂停10秒后恢复；完成一次正常通关，并分别触发生命耗尽与倒计时耗尽。连续重开10次，检查对象数量、计时速度和输入没有累积。可用调试观察辅助检查，但不能以作弊入口或直接设置胜利代替真实通关。保留步骤、实际结果和桌面/手机操作证据；未完成通关或未做的检查如实列出，不以理论跳跃计算声称已通关。

# 鹈鹕叉车驾校

提示词版本：pelican-prompts-4。本阶段预算：60分钟。

使用所附 Three.js + enable3d 及其 Ammo 物理集成，从空场景制作可实际驾驶搬运的《鹈鹕叉车驾校》。预算60分钟；实现给定仓库的一局，不增加车辆升级、关卡编辑器或精确液压模拟。

## 材料与技术边界
先读 materials/START.md、materials/CONTRACT.md 和 materials/warehouse.json。按给定布局、米制尺寸、Y向上坐标及控制参数实现；物理运行资源只从本地 vendor/ammo/ 加载。使用Three.js基础或自定义几何体程序化建模，不导入外部GLTF/GLB、图片贴图或生成式3D资产。不要修改地图、碰撞契约或采样工具来通过验收。

## 模型、层级与联动
叉车有可分别辨认的车身、驾驶室、座椅、四个车轮、门架和两根货叉；驾驶位坐一只白色身体、长喙、明显喉囊的鹈鹕。仓库包含地面、货架、路障、三个不同颜色货箱、同色交付区及阻挡车体的边界。比例、材质和灯光应让模型和可行驶区域清楚可辨。
建立清楚的父子层级：车轮随车辆前进/倒退滚动，转向轮偏转，货叉沿门架升降，驾驶员随整车运动。车宽由统一参数管理，各部件相对位置与可见模型、碰撞体协调。可以使用简化刚体，不要求真实车辆悬挂或液压动力学。

## 驾驶与搬运闭环
W/S前后驾驶，A/D转向，Q/E升降货叉，空格制动，P暂停；界面明确升降键对应方向。驾驶与搬运由玩家操作，不能用自动寻路或预录脚本代替。车、货箱与地面、墙及静态障碍有合理碰撞。
货叉降到箱底、方向和位置对齐、伸入箱底后，升叉可托起一箱；允许契约规定的吸附辅助，不允许隔空按键拾取。对齐夹角≤15°、横向偏差≤0.25米、高度差≤0.15米、水平伸入≥0.3米；降低至箱底接近地面（≤0.1米）后释放。以 CONTRACT.md 为判定依据，合理容差须记录。
释放后，箱子水平投影完全进入同色区域，箱底距地≤0.05米、水平速度≤0.1米/秒连续0.5秒才计交付；每箱仅一次。错色、只驶过或未落地均不计分，释放后不能穿地。货箱尺寸与初始布局保持一致。

## 状态、镜头和引导
本局120秒，三个箱子均正确交付即胜利，超时失败。提供开始、游玩、暂停、胜负结算、重开；HUD显示剩余时间、交付进度及必要操作提示。暂停时物理、车辆、货箱、计时和交付稳定计时冻结；结算后不能继续驾驶计分。重开恢复车辆、箱子、计时与分数。
默认第三人称跟随镜头，驾驶方向和目标清晰，靠近墙或货架时避免严重遮挡。在暂停下提供模型检查模式，可从前、侧、后、斜上方观察；检查中游戏保持暂停，退出检查不改变车辆、箱子及计时状态，再由玩家恢复游玩。

## 界面清单与视觉完成度
提供开始界面、驾驶HUD、暂停面板、模型检查面板及胜负结算。开始界面说明三箱同色交付目标、120秒限制和完整控制键，点击开始才计时；HUD将剩余时间、已交付数量、当前搬运箱和简短拾放提示分区展示，不遮挡车头与货叉。暂停面板提供继续、模型检查及重新开始；检查面板能选择前/侧/后/斜上视角并明确返回；结算写明成功或超时及实际已交付数量，给出重试入口。
仓库采用统一材质与克制灯光，让车辆、货箱、货架、地面边界易于区分。交付区域有与货箱对应的颜色和文字标记，不能仅靠相近颜色识别；透视与比例自然，避免物体悬浮、穿插、全黑或过曝。界面用一致字号、留白、按钮与面板风格，信息对比清楚；不要让大面积不透明面板常驻遮挡驾驶区域，不以调试器控件或alert代替正式界面。不要求增加贴图、后处理或移动端驾驶，从已有几何体、材质和灯光获得完成度。

## 实际验证与性能
真实驾驶执行转向、升降、制动、撞墙、对齐拾取和落地释放；尝试错色、重复交付、只驶过区域，再完成三箱搬运。保留多视角或线框、模型源码位置及关键操作记录；失败或未通关如实说明。
按1280×720、DPR1的生产构建，预热10秒后采样60秒，tools/performance.js 的帧间隔P95≤33.3ms；不得降低分辨率或删除任务物体。连续重开10次记录 resources(renderer) 原始值，检查稳定后是否持续增长，固定缓存不要求归零。记录硬件、浏览器、采样条件、暂停恢复和超时失败检查；不能用估算帧率代替原始数据。

## HTML 交付约定
最终入口必须为 `output/index.html`。图片、脚本、样式、数据与物理运行资源全部存于 `output/` 内并使用相对路径引用。页面应能通过普通本地静态HTTP服务打开，也能在iframe中运行；不依赖外网、宿主父页面、固定端口、外部API或额外后端进程。允许使用多个本地资源文件。
React/Phaser/Three.js项目执行 `npm run build` 生成该入口，已有构建配置使用相对资源路径。研究题制作含方法、图表、原始结果链接与结论的HTML报告；SVG题在HTML中内联动画，SVG内部仍不得使用JavaScript。
展示环境使用仅允许脚本的沙箱iframe，不提供同源身份。页面状态使用内存，不能依赖localStorage、IndexedDB或Service Worker；本地资源与ES模块由预览服务提供跨来源读取支持。
交付前用本地静态服务检查实际功能。另写 `output/DELIVERY.md`，说明成果路径、启动方式、已运行检查、未运行检查和已知缺陷。不要以占位页或原始起始页代替成果。
