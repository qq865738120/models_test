# 正式开测前的预跑清单

当前工具和材料为试运行版。不要把工程构建通过写成游戏可通关或基准公平性已经验证。

- 所有模型：同操作系统、锁文件、模型档位、客户端工具、上下文与预算；按材料哈希分组；独立新会话、三次运行；明确哪些客户端权限无法统一。
- 01 SVG（`01-svg`）：固定浏览器，确认SMIL与CSS动画采样方法，覆盖三个循环及踏板四相位。首次交付与追加分别留录屏。
- 02 静态网页（`02-static`）：核对本地鹈鹕资料卡来源与正文准确性，实际检查桌面和移动端阅读、图片资源、导航与追加儿童内容。对照图例复核视觉评分，避免把某一种配色或布局当作唯一答案。
- 03 全栈派单（`03-dispatch`）：确认Node服务与固定10000条订单、公开HTTP和错误码规范一致；验证输入校验、并发原子性、正常与乱序响应、空结果、查询失败和派单失败。实际操作五页、弹层及追加URL恢复流程；用生产页面校准真实反馈的观察方法。
- 04 2D（`04-game2d`）：以当前提示词及提供的素材核对作品，关卡由实现者设计；开发者实际操作取得三包并通关；站上移动平台、掉出地图、受击、暂停及重开十次；追加易碎包也实际通关。主持人用正常输入核对实际游戏规则，保存参考实现、操作路径与原始录屏。
- 05 3D（`05-game3d`）：确认本地Ammo正确加载；原车宽及加宽20%均能真实拾放三箱通关；错色、驶过、重复交付和穿模样例应被验收方法识别。统一设备、1280×720与DPR1，校准60秒采样及十次重开资源趋势；建模与画面人工按图例和实际多视角表现评分。
- 06 长文本客观题（`06-memory`）：逐题复核36道初始题、12道追加题的来源依据、答案及证据分档；论文题核对跨论文必要性，小说题核对跨章节必要性。由不同模型先盲答再比较，每个争议回到原文与独立计算裁决，测试前冻结。用正确、错误、漏答、额外题号、重复题号和非法JSON核验评分脚本；确认答案、依据及未开放的追加题只保留在主持人端。
- 第1、2、4、5题由主持人按当前阶段提示词及各维度锚点实际核验（`materials/EVAL.md` 仅为交付说明），用0–10分滑块评分，步长0.5分；不添加未公开要求，不以脚本通过数代替人工判断。第3题按 `materials/API.md` 自动核验纯HTTP接口：整维度全部通过记1、存在失败记0、环境不可观察留空；前端功能、视觉与交互仍人工评分。第6题继续自动答案评分。浏览器和游戏开发检查工具仅用于旧契约调试，不写入成绩，也不用于要求新作品复刻固定坐标、布局或内部接口。
- 第6题环境：在实际候选权限下渲染一页PDF，确认材料可读、输出可写、主持人答案与父目录不可读、受保护文件不可写且外网被拒绝。保存实测结果；命令沙箱通过不等于整个客户端拥有独立系统用户或虚拟机隔离。
- 记录阶段预算是否合理，基础设施故障重试规则与评分锚点；确认后冻结材料，所有比较对象使用同一冻结版本。

预跑证据例如保存在评测者控制的 `verification/preflight/`。真实完成后执行：

```sh
python3 bench.py calibrate --note "verification/preflight/ 中的参考实现、视频、测量与审核记录"
```

该命令仅保存主持人声明；不会替你核实这些证据，也不会产生模型成绩。
