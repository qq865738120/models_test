# 鹈鹕测评 v1.0

面向评测视频的本地主持人工作台：SVG动画、鹈鹕科普静态网页、React＋Node.js派单平台、Phaser 2D游戏、Three.js＋enable3d 3D游戏、长文本客观答题。前五题交付 `output/index.html`，新版第6题只交付 `output/answers.json`，模型由你选用的本地编程智能体运行。当前使用 [六题标准 r14](llm-evaluation-standard-r15.html)；原会话的 [五题标准](llm-evaluation-standard.html) 保留不改。已有轮次的固定题目、原评分标准和已存分数保留；人工评分界面展示当前维度，重新保存时记录新评分版本。

## 六题标准 r11：人工核验作品，自动判定派单接口与客观答案

新版顺序为：01 SVG动画、02 鹈鹕科普静态网页、03 派单平台、04 2D游戏、05 高画质3D叉车游戏、06 长文本客观题。题号、内部任务ID和工作区目录统一为 `01-svg`、`02-static`、`03-dispatch`、`04-game2d`、`05-game3d`、`06-memory`，按目录名排序即为题目顺序。原始、[r6](llm-evaluation-standard-r6.html)、[r7](llm-evaluation-standard-r7.html)、[r8](llm-evaluation-standard-r8.html)、[r9](llm-evaluation-standard-r9.html)、[r10](llm-evaluation-standard-r10.html) 标准保留作为版本文档。r11将SVG评分收敛为空间关系、脚与踏板同步性、构图与动画表现三项；2D游戏不再单列HUD/键盘触屏输入及引擎交付分，3D游戏不再单列本地物理、性能与资源分。第2题仍使用视觉和内容三项，第3题保留纯HTTP接口自动判分；r12将第6题扩展为72道初始题和24道追加题，标为中级，题库经不同模型盲审核对后冻结。r13进一步明确静态页从空白画布自由创作，允许自行编写图形、动画和模型；评分版本仍沿用r12。r14将第6题改为18道初始结构化短答题和6道追加题，强化跨材料条件联立及信息推理；前五题内容与已有成果保留。删除独立评分项不取消基本任务要求，旧分数不会自动重算。

## 一键开始

拉取仓库后，macOS双击 **`启动鹈鹕测评.command`**（原 `一键初始化.command` 也会打开同一工作台）。macOS、Linux、Windows也可在仓库根目录执行：

```sh
python3 bench.py launch --open
# Windows若使用python命令：python bench.py launch --open
# 端口占用时：python3 bench.py launch --port 8797 --open
```

需要本机 Node.js/npm 与 Python 3.9+。启动时先只读校验已导入的历史作品；首次联网安装**工作台自身**依赖，之后依赖锁文件或Node/npm版本变化时重新安装，每次构建工作台后打开 **http://127.0.0.1:8787**。此流程不安装题目依赖、不下载论文，也不执行题目构建命令。保留启动终端，关闭终端会停止服务，数据不会丢失。

进入「演示测评」，从顶部选择历史模型、底部选择题目；已有作品时直接进入「作品」章节，可实际操作派单后台、2D/3D游戏，播放SVG动画、浏览静态科普页或查看长文本题答案。顶部切换初始/追加交付，作品旁可切换历史版本，也可重新加载和全屏操作。没有交付的阶段显示“本阶段暂无作品”，不生成示例成果或分数。

### 历史作品与开源仓库

仓库保留每题**已经构建并导入**的HTML作品及完整相对路径资源。工作台从 `data/artifacts/<成果编号>/files/index.html` 提供作品，浏览器运行其中的JS、CSS、图片、数据和WASM；查看与操作历史作品不依赖 `runs/` 中的源工程、`node_modules`、`.runtime` 或 `.prepared`，也不需要打开每题的开发服务器。首次安装工作台依赖后，历史预览只使用本机服务。

维护仓库时需要一起提交：

- 工作台与题目源码、`package.json`、`package-lock.json`。
- `runs/<轮次>/control/run.json`、`review.json`、`rubric.json` 等轮次和评分记录；现有历史快照保留原样。
- `data/artifacts/` 中作品的 `manifest.json`、`files/index.html` 及**全部资源**。这里的打包JS/CSS和WASM属于历史交付证据，不能因为可以重新构建而省略。

`node_modules/`、`.runtime/`、`.prepared/`、工作台和题目根目录的 `dist/`、后台临时任务记录、验证浏览器配置均由Git忽略。本机现存缓存可继续使用；忽略规则不会删除它们。成果目录内实际使用的 `dist/` 资源仍可提交。大型录屏和完整备份可另放版本发布附件，但默认展示所需的资源应随仓库保留。

提交前执行：

```sh
python3 bench.py verify-history --tracked
```

该命令校验每个已导入版本的轮次/题目/阶段关联、入口、文件数量及内容哈希，并确认历史展示必需的记录和资源已纳入Git；新成果须先 `git add` 再检查。它不执行作品、不修改评分或基线、不依赖准备包。普通 `verify-history` 不检查Git跟踪状态，也会在 `launch` 时自动执行。校验只能确认归档与导入时一致，不能代替浏览器交互验证。

`check` 检查的是原始测试工作区，包括当时的预装依赖；克隆时排除依赖后执行它，可能报告依赖缺失。这与历史归档作品是否完整是两回事。请勿通过重写历史基线或重新安装旧题目来“修复”历史成绩。需要修改源码时在独立开发副本中安装锁定依赖；需要开展新评测时使用下面的准备、初始化流程。

### 开展新评测

进入「后台管理」，填写模型名称、Harness、思考强度、测试题目和重复编号，点击「初始化测试项目」。材料未准备时先点「准备 v1.0 材料」；准备阶段联网安装锁定依赖并下载论文，之后初始化离线复制。每题拥有独立工作区，不会覆盖原轮次。准备包不随Git分发，长文本题的用户提供材料需按下文说明另行准备；仅查看历史作品不需要这一步。

已构建前端时可直接启动：

```sh
python3 bench.py serve --open
# 端口占用时：python3 bench.py serve --port 8797 --open
```

工作台使用管理端口和紧邻的成果预览端口（默认8787/8788），均仅监听本机。前端修改后在 `web/` 运行 `npm run build`；开发时先启动本地服务，再在 `web/` 运行 `npm run dev`。

## 主持人操作流程

1. 在「后台管理」新建模型轮次，回到「演示测评」选择题目。右上角「主持人工具」可复制本题工作区路径，将本地智能体的项目根目录设置到该目录并开启新会话。
2. 在主持人工具中「开始计时」，翻到「提示词」章节点击「复制完整提示词」。复制内容包含任务、公共规则与该题交付要求；第6题包含公开题目和权重，标准答案与未开放的追加题保留在主持人端。
3. 模型交付后停止写入，在主持人工具中检查材料并冻结本阶段。前五题导入 `output/index.html`；新版第6题导入 `output/answers.json`，工作台自动归档答案、生成预览并评分。冻结后导入的是冻结副本，修改工作区不会改变它。
4. 第1、2、4、5题导入后，由主持人实际检查页面、游戏规则与操作效果，全部维度用0–10分滑块评分，步长0.5分；视觉与体验结合参考图例。第3题先运行接口评分脚本，其余维度人工核验评分。未核验或未评分可保存草稿。第6题导入即按冻结标准自动评分，对错题无部分分，证据分档单选题可得0、50%或100%权重。
5. 需要追加测试时，先冻结初始阶段，再在主持人工具中「开放追加任务」。顶部交付阶段可切换，两阶段独立展示、留档与评分。
6. 顶部模型选择器切换历史轮次；「成绩对比」按页展示综合分、能力雷达、逐题比较、总表和轮次记录。后台可修改模型名、记录备注、归档或恢复轮次，并导出CSV与JSON。

演示区与成绩对比使用暖白配色、16:9固定画幅，根据窗口等比缩放，没有整页滚动。底部可切换题目、章节和前后页；支持 ← / →、PageUp / PageDown、Home / End（输入框和提示词滚动区中不触发翻页）。右下角「全屏演示」隐藏顶部导航，作品另有独立全屏按钮。翻页动画遵循系统的“减少动态效果”设置。后台管理保留普通滚动布局；作品自身的页面仍可在内嵌区域滚动。页面不预填任何模型成绩。

### 评分口径

第1、2、4、5题按各自专属维度计算，权重合计100%。主持人实际检查各维度列出的功能与表现，对照0/5/10锚点，用滑块评0–10分，允许0.5分中间档；未核验或未评分的维度为空。单题得分为 `Σ(维度分 × 权重 ÷ 10)`。第3题初始的查询10分、原子派单20分、校验10分，以及追加的接口回归10分，由接口脚本整维度二元判定：该维度全部指定检查通过记1、存在失败记0、环境不可观察留空；自动分为 `Σ(判定值 × 权重)`，其余维度仍以人工滑块分除以10加权。新版第6题的对错题正确记1、错误记0，证据分档单选按冻结标准记0、0.5或1，单题得分为 `Σ(判定值 × 题目权重)`，满分100；多选全对才得分，不给部分分。完整轮次总分为六题等权平均。在相同材料与评分版本下，同名模型、Harness及归一化思考强度均相同时，汇总完整轮次均值并显示轮次数。Harness或思考强度未记录时，每轮单独展示，不自动合并。成绩页可按Harness和思考强度筛选。

初始与追加分开对比；材料哈希和评分标准版本不同的轮次分开选择。未评分项是空值，明确打0才是零分。只有该版本全部题目均完成评分、各成果材料完整性通过的轮次进入总榜。单题测试仍可在工作台与逐轮表查看，但不生成完整套题综合分。

评分绑定具体成果版本。第6题每次导入答案自动生成对应评分，前五题导入新HTML后需重新评分；旧成果与旧评分继续保留。评分版本保存在新建轮次的 `control/rubric.json`，第6题标准答案及校验值也随轮次固定，后续修改全局标准不会重算旧轮次。模型名称、推理档位、客户端与外部干预仍需主持人如实记录并保持分组可比；自动分组不能识别未记录的条件差异。

### 第6题自动评分

客观题版本为 `longread-qa-v4`，难度标记为“中级”。初始18题，物理、数学、小说各6题，权重分别34、33、33分；追加6题，每类2题，两阶段分别满分100。论文题联立多篇材料中的适用条件与计算关系，题干及答案字段不提供目标论文编号；小说题重建跨章节的因果、知识时点和信息可达关系。只提交短答案：按字段顺序以英文分号连接整数、精确有理数或代码序列。每题全部字段正确才取得权重分；等值分数、空白和代码大小写规范化，但不接受近似数、运算表达式或多余字段。出题模型与盲审模型分别核对原文、推导、唯一性和材料依赖，第三模型审查题干线索，另以精确算术验证评分器。冻结后才启动被测会话，不根据作答调整答案或权重。

只为第6题建立独立新轮次重测；第1–5题的历史成果和评分、旧第6题成果和分数保留。旧版题库仍使用自己的冻结答案，显示难度标签调整为中级不改变旧题目或分数。新旧题库成绩按版本区分。

模型只提交一个JSON对象，例如 `{"P01":"B","P02":"AC"}`（仅演示格式，不代表正确答案）。单选填写一个选项字母，多选填写字母组合；不要求推理、引用、报告、页面或 `DELIVERY.md`。题目写明单选/多选和权重。大小写、字母间空白及多选顺序差异不影响结果；重复字母、非法选项、漏选、多选、漏答均判错，重复题号该题判错。额外题号忽略并报告，无法解析的JSON整份计0分。

工作台导入答案后自动评分，也可在评测管理目录执行：

```sh
python3 scripts/score_answers.py --run RUN --phase initial --output score-initial.json
# 等价入口：
python3 bench.py grade --run RUN --phase initial
# 核对另外保存的答案文件：
python3 bench.py grade --run RUN --phase initial --answers /absolute/path/answers.json
```

默认优先读取本阶段冻结快照，未冻结时读取工作区的 `output/answers.json`。脚本使用该轮次私有标准答案，输出逐题满分/部分分/零分、权重、得分、总分及文件哈希，报告拒绝覆盖；`score_task6.py`与`score_answers.py`均为第6题评分入口。脚本不会改写工作台评分，正式入档请使用工作台导入答案。评分报告含标准答案，仅供主持人保管。

完成题库审阅冻结后，可使用 `python3 bench.py revise-prepared` 离线修订材料（保留旧包）；首次准备使用 `python3 bench.py prepare`。源题目在 [新版题库](research/longread-qa-v4/questions.json)，标准答案与来源依据在同目录的 `host/` 中；初始工作区只分发18道初始题，不分发答案、评分脚本或追加题。

主持人可运行 `python3 scripts/verify_longread_bank.py` 核对引用、权重及全部选项组合的评分；原文含义与跨材料必要性另由独立审阅核验。macOS 准备阶段会编译单题内的 `tools/pdf-page`，模型可离线渲染任意 PDF 页核对公式，使用方法随材料提供。`scripts/run_memory_candidate.py` 仅接受全新第6题单题轮次，先实测读写、网络限制和 PDF 渲染，再启动独立 Codex CLI 会话；日志与答案分开保存，不将主持人答案传入会话。

第2题从空白HTML起始。新版提示词与事实材料不规定配色、字体、布局、章节结构、浏览方式或动效方向，也不要求固定data-topic、每区字数、字号及主题容器；只保留美观酷炫、内容全面准确和可离线运行的静态交付目标。旧成果、旧提示词与分数保留，后续新建测试采用自由创作版提示词。

演讲模式复用评分汇总布局，展示总分和各维度已保存结果，不展示提示词和逐项评分操作。汇总页移除“本题加权得分”、求和解释、保存状态和保存按钮；人工评分仍在单项评分页保存。

### 作品人工核验与派单接口自动评分

第1、2、4、5题不再使用「自动核验」评分流程。导入作品后，主持人逐项检查并操作评分滑块。第3题仅纯HTTP接口使用独立脚本，前端功能、视觉和交互仍人工核验；不以浏览器脚本通过数替代人工判断。

SVG检查空间连接、踩踏同步和完整动画表现；静态页检查全面准确的内容与视觉完成度；派单检查真实HTTP、输入校验、并发原子性、页面联动与竞态；游戏通过实际操作核对玩法、规则、视觉与手感。3D帧时间仍可按公开要求以1280×720/DPR1预热10秒、采样60秒，作为基本运行要求的核对，不单独计分；软件渲染或不可比较的环境保留未核验。截图不能代替功能操作，也不能单凭源码推定行为正确。

仓库保留的浏览器与游戏检查代码仅供开发调试和回归验证，不属于主持人评分入口，不能替代人工核验。第3题接口评分脚本直接请求独立归档Node服务，不启动浏览器，不评价前端、视觉或交互；每个接口维度必须全部检查通过才取得完整权重。


各题 `materials/EVAL.md` 仅说明工作台入口、相对资源和 iframe 运行条件；派单另保留 `materials/API.md` 与 `materials/HARNESS.md` 的真实 HTTP 接口、启动和打包约定。项目文件不再要求固定 DOM 标识、游戏观测接口、测试场景或按键重放。题目内容由当前阶段提示词决定，项目材料不再另加平台坐标、仓库布局、物理参数或 HUD 排版要求。追加专属要求和答案不会提前分发。

派单使用独立Node.js HTTP服务，数据只存进程内存，刷新页面保留、重启服务复位；不要求数据库。项目构建交付前端及 `output/server/index.mjs`、固定种子。工作台不会因导入或打开页面就执行服务；预览时按页面提供的命令显式启动：

```sh

```

### 本地保存与备份

后台「模型与历史轮次」每行提供删除按钮，确认模型及运行编号后删除整轮测试。有关联后台任务正在排队或执行时禁止删除。删除后列表、成绩对比和当前选择会同步更新。

删除会把工作区、评分和未被其他轮次引用的成果移入 `.trash/runs/<运行编号>-<唯一编号>/`，保留 `deletion.json` 原始路径记录；共用成果保留在原处。回收目录不会自动清空，若需要找回可按记录手动恢复，目前不提供界面恢复入口。

- `runs/<轮次>/tasks/`：各题工作区；`control/`：提示词、元数据、固定评分标准、评分记录、原始快照。
- `data/artifacts/`：每次导入的独立HTML成果及资源、校验清单；`data/jobs/`：后台操作结果。
- 同时备份 `runs/` 与 `data/` 即可保留项目、成果和分数；若需保留已删除测试，还需备份 `.trash/`。CSV/JSON仅导出记录，不包含HTML资源。`.prepared/`是可重建的材料包。
- `node_modules/`、`.runtime/`和浏览器配置不属于成果；无需提交或纳入历史展示包。完整开展新评测所需的材料准备与历史作品预览相互独立。

作品由独立端口以只读方式展示，iframe不允许访问父页面，管理请求校验来源与会话令牌。HTML使用本地相对路径，不访问外网或浏览器持久存储。新版派单题可连接主持人显式启动的独立Node内存服务；其他题仍静态交付。导入、浏览和工作台启动不会自动执行候选后端或构建命令。旧版pilot轮次保留在后台历史库，不改写其提示词、工作区与快照，也不与v1.0混榜。

## 一次评测的操作

以下命令都在**评测管理终端**执行。`RUN`替换成初始化时打印的运行编号。

```sh
# 保存本轮环境；温度不可调时记录“不可调”，不要假装统一。
python3 bench.py record --run RUN --agentClient "客户端+版本" --browser "浏览器+版本" --reasoning "原生档位名称" --reasoning-level 3 --hardware "机器配置"

# 将第一题初始提示词复制到macOS剪贴板。
python3 bench.py prompt --run RUN --task 1 --copy

# 主持人发送提示词时记录开始。到时由主持人停止智能体。
python3 bench.py start --run RUN --task 1

# 交付或超时：先停止智能体及写入文件的服务，再校验和留档。
python3 bench.py check --run RUN --task 1
python3 bench.py snapshot --run RUN --task 1 --phase initial

# 释放并复制固定追加需求；此命令要求有效初始快照已冻结。
python3 bench.py prompt --run RUN --task 1 --phase change --copy
python3 bench.py start --run RUN --task 1

# 追加阶段结束。
python3 bench.py check --run RUN --task 1
python3 bench.py snapshot --run RUN --task 1 --phase change
python3 bench.py status --run RUN
```

即使初始实现失败，只要材料完整性有效，也可冻结并进入同一追加阶段。已有快照不能重写；追加修复不会改变初始快照。快照包含源码、原始材料、结果与依赖锁文件，并记录内容哈希；省略 `node_modules`、可重建的 `dist` 和Git目录。管理员快照文件设为只读用于防误操作，同一宿主用户仍能主动解除只读，因此不称其为防篡改存储。

`check` 检查规则、依赖、锁文件、工具与材料的修改，也拒绝项目外链接和硬链接。它不评判功能正确性，不证明没有越界读取。违规材料可用 `snapshot --allow-invalid` 保留无效样本，但该样本不能继续成为有效成绩。

人工介入使用 `record --intervention "实际提示或干预内容"` 留档。每题独立重复三次；失败也保留。费用和token等在 `control/run.json` 中按可核对的来源记录，工具不会编造数值。第1、2、4、5题由主持人按公开契约实际核验功能、视觉、表达和手感，再逐项滑块评分；游戏通关可用普通按键重放辅助核对并保留录屏。第3题只对纯HTTP接口自动判分，其余维度人工评价。第6题继续按冻结答案自动评分。

## 文件限制与公平条件

公共规则禁止读取其他项目、主目录、客户端历史、全局记忆、skills、MCP私人数据、其他轮次产物和隐藏答案；禁止外网、额外模型/智能体、生成素材、改写材料与评分工具。执行Node/Python/浏览器及必要系统运行库有明确例外，不能利用它们搜寻业务资料。

**默认本地模式只有规则约束。** `AGENTS.md` 和 `CLAUDE.md` 帮助不同客户端收到同样的限制，但不是操作系统权限。客户端的全局记忆、外部连接器、搜索、子智能体、工具自动批准等须由主持人关闭或统一配置；不能关闭时记录差异并分榜。上游模型请求由客户端发送，与题目程序的禁止外网区分。初始化脚本不能更改所有客户端的权限，也不能自动中止宿主模型采样。

```sh

# 仅准备阶段：在运行镜像内生成Linux依赖。旧宿主材料会备份。
```

容器断网，仅挂载本次单题目录；材料、规则、工具与依赖再单独只读挂载。禁用额外权限，使用非root用户，限定CPU/内存/进程数，临时文件放在容器 `/tmp`。镜像ID在真正启动时写入元数据。运行镜像需与准备依赖的操作系统一致：**macOS生成的 `node_modules` 不能直接用于Linux容器**；先在Linux准备环境中生成同一锁文件对应的材料，再以 `--profile sandbox` 在宿主初始化。脚本会拒绝混用平台，不能一边测试一边安装。切回本地模式时在宿主显式 `prepare --rebuild`。这一入口目前是静态校验过的终端隔离方案，当前机器无Docker，未进行容器实测。

**只有所有智能体文件、终端及浏览器工具都运行在受限环境内，才可记录完整强制隔离。** 只把游戏或一个终端放入容器，宿主客户端仍可读文件，不算完整隔离。该工具默认始终保留“规则约束”或“终端容器，完整接入未验证”的真实状态。容器的浏览器要在容器中运行；不要为方便而关闭断网、挂载整个主目录或Docker socket。

Docker隔离与网络设置依据：[Docker运行容器官方文档](https://docs.docker.com/engine/containers/run/)。

## 思考强度：统一五档

后台提供1档（最低）、2档（较低）、3档（中等）、4档（较高）、5档（最高），按各模型自身的有序原生档位等距归一化。同档只表示相对位置，不代表跨模型算力或实际思考量相同。

| 原生档位数 | 从低到高对应的统一档位 |
| --- | --- |
| 2 | 1、5 |
| 3 | 1、3、5 |
| 4 | 1、2、4、5 |
| 5 | 1、2、3、4、5 |

一般公式为 `1 + floor(4 × i / (n - 1) + 0.5)`，i从0起，n为可调档位数；超过5个原生档位会合并相邻档位。只有固定档位或不能调节时选择“不支持设置”。默认或自适应设置无法确定位置时保留“未记录”，不推断为中档。这两项是独立记录状态，不属于五档。

该字段记录实际测试条件，不自动配置模型客户端。新建、编辑、筛选和CSV/JSON导出均支持，修改保留历史。CLI通过 `init --reasoning-level 3` 或 `record --run RUN --reasoning-level 3` 设置（支持1至5和unsupported）。旧 `--reasoning` 原生描述继续保留，不自动映射或覆盖。
