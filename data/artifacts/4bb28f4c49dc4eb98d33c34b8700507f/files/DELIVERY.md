# 鹈鹕叉车驾校 · DELIVERY

## 入口与启动

- 入口：`output/index.html`
- 本地静态启动（相对路径、无外网、无后端）：
  ```bash
  cd output
  python3 -m http.server 8000
  # 打开 http://127.0.0.1:8000/index.html
  ```
  也可用 `npm run preview`（构建工程预览），或在支持相对 ES 模块的静态服务/工作台 iframe 中打开。
- 构建：`npm run build`（`tsc --noEmit && vite build`），已生成最新 `output/`。HTML、CSS、JS、Ammo 都在 `output/` 内，使用相对路径。
- 本地运行资源：`output/vendor/ammo/ammo.wasm.js`、`ammo.wasm.wasm`；无 external model/texture，全部几何与贴图为程序化生成。无 localStorage/IndexedDB/Service Worker。
- 启动需要 HTTP（ES module 与 wasm 相对加载）；不能以 `file://` 打开。

## 操作

| 按键 | 功能 |
| --- | --- |
| W / S | 前进 / 后退 |
| A / D | 左 / 右转向 |
| Q / E | 升叉 / 降叉（降至低位自动释放货箱） |
| 空格 | 制动 |
| P | 暂停；暂停面板内可做前/侧/后/斜上方模型检查 |
| C | 跟随 / 近景视角切换 |
| Enter | 开始训练 |
| R | 暂停或结算时重开 |

## 实现要点

- 30×24 m 仓库，Y 向上；三只 1.1×1.0×1.0 m 货箱（红/黄/蓝）位于西侧备货线，东侧同色 2.9×2.9 m 交付区，120 秒内交付 3 箱获胜。
- 程序化叉车：分件车身、配重、散热/灯具/踏板/护栏、四轮轮胎+胎面+轮毂+轴心、驾驶室立柱/顶架/座椅/方向盘/仪表/操纵杆、双导轨门架、升降托架、链条/液压缸、双货叉；车轮随速度滚动，后轮转向偏转，货叉沿门架升降。
- 鹈鹕驾驶员：体块、S 形颈、长喙、立体喉囊、眼/瞳、羽片、翅膀、脚爪、反光背心与安全帽；坐在座椅上，随车运动并有轻微呼吸/转向摆动。身体已缩放到驾驶室内部，无与方向盘/座位明显穿插。
- 材质：车漆（clearcoat）、金属/镀铬、橡胶、皮革座椅、羽毛、喙/喉囊、程序化混凝土地面、木箱、瓦楞墙、危险条纹、灯箱/标牌（Canvas 纹理）。RoomEnvironment 环境反射 + ACES 色调映射 + 方向主光/补光/半球光/阴影。
- 物理：Ammo 用于三只货箱（动态刚体、重力、地面/墙/货架/道具碰撞、堆叠）与叉车运动学刚体；叉车与静态环境的约束用圆-矩形简化碰撞，车宽/轴距统一参数。货箱不会穿地（同步时做高度保护）。
- 状态机：ready / playing / paused / won / lost；暂停冻结物理、计时、稳定交付计时；重开恢复车辆、三箱、计时、分数和交付区状态。

## 搬运判定（实测参数）

- 对位吸附：朝向夹角 ≤ 15°、横向偏差 ≤ 0.25 m、叉面与箱底高度差 ≤ 0.15 m、货叉伸入箱底 ≥ 0.30 m、一次仅一箱；满足后在低位按 Q 升叉才会吸附。
- 释放：降叉至箱底距地 ≤ 0.1 m（实现为货叉降至最低时自动释放），箱子落回 AMMO 刚体，不穿地。
- 交付：释放后箱子水平投影完全在同色区、箱底 ≤ 0.05 m、水平速度 ≤ 0.1 m/s，连续 0.5 s 才计分。错色、悬空、仅驶过、已交付（锁定）均不计分。
- 实现容差：箱底检测 `y-0.5`（半高 0.5 m）；区判定按货箱 4 个角做 OBB 包含；释放后箱体 yaw 吸附到最近的 90° 以稳定停放；Ammo 箱体锁定 X/Z 翻转，仅允许水平移动（便于对位与堆叠稳定）。

## 已检查（真实运行）

浏览器：本机 Chrome Headless + ANGLE Metal（Apple M5 Pro），1280×720，DPR 1，通过 CDP 发送真实键盘事件/鼠标点击截图。未使用的检查会明确标注。

- 构建：`npm run build` 通过，无 TS 错误。
- 启动：Ammo 本地 wasm 成功加载；开始前不计时（ready 120 s），点击开始后计时开始。
- 真实驾驶与托举：W 直行至黄箱前 (−9.4, 0.5)，朝向 π；货叉 0.10 m，按 Q 后 lift=0.70 m，`carrying=yellow`，箱底随叉上升；松开 Q 不再上升。
- 真实搬运并交付：黄箱运至 (8.4, 0.4)，转向约 1.5 rad，降叉释放；黄箱落在同色区内（约 (10.1, 0.5)），0.5 s 稳定计时后 `score=1/3`，芯片变为完成。实测截图 `verification/09-delivery.png`。
- 错色：黄箱放入蓝色区，稳定后仍 `score=0`，HUD 提示“颜色不匹配：黄色货箱应放入黄色交付区”。
- 悬空：把蓝色箱置于蓝色区上方（箱底约 1.0 m），等待 1.8 s 分数不变。
- 重复交付：已交付箱从物理世界移除并在拾取候选中跳过；把车移到已交付箱旁，分数不增加。交付稳定计时仅对未携带、未交付的箱子累计。
- 暂停冻结：暂停前后 `timeLeft=116.254`（1.2 s 暂停期间完全不变），货箱 y/lift 不变；暂停内切换前/侧/后/斜上方视角，点击“退出检查 / 跟随视角”后仍为 paused；恢复后继续计时。
- 重开：结算/暂停重开后车辆回到 (−9.4, 4.6)，三箱回到 (−11.8/−9.4/−7.0, −1.2)，`score=0`，计时约 119.3 s。
- 胜负界面：胜利界面（3/3）和超时界面均已显示；见下方限制说明。
- 10 次连续重开资源：`geometries 199 / textures 33 / programs 22 / draw calls 171 / triangles 48502` 每次相同，无持续增长。内存 `usedJSHeapSize ≈ 18.3 MB`。
- 性能：将 `tools/performance.js` 原文注入页面，调用 `window.bench.frames({warmupSeconds:10, sampleSeconds:60})`：
  - 1280×720、DPR 1，样本 3600，**P95 = 16.7 ms**（≤ 33.3 ms），采样耗时 70.0 s。
  - 渲染规模约 171 draw calls / 48.5k triangles（合并静态几何后）。

## 未完成 / 已知限制（如实记录）

- **没有在本会话内完成“三箱全程真实键盘搬运通关”**。真实驾驶已完成黄箱的托举、运输、落地与 1/3 计分，并验证了错色/悬空/重复/暂停/重开；但用于自动验证的外部输入驾驶脚本在返程对位时多次卡在货架/立柱边界，未能在 120 s 内完成第二、三箱。胜利与超时画面是用调试接口把箱体放入交付区/缩短内部计时验证的 UI 与状态，不是三箱真人通关记录。游戏本身可正常驾驶、托举和交付。
- 真实 120 s 超时没有实际等待完整 120 s；超时状态通过把内部 `timeLeft` 设为 0.3 s 验证，逻辑相同但非全时长实测。
- 车辆物理为简化运动学：加减速、后轮转向、圆-矩形环境碰撞、货箱为 Ammo 刚体；无悬挂、液压倾斜或翻倒模拟。
- 货箱仅允许水平位移与绕 Y 旋转；释放时 yaw 吸附到 90° 倍数，以便稳定停放和判定；这是为可玩性与稳定性的合理简化。
- 相机遮挡使用射线-AABB 简化；极端贴架/角落仍可能出现短暂穿帮或拉近。
- 未做移动端触控；未加入音效。
- 性能数据来自本机 Chrome/Metal，工作台机器不同可能略有差异；截图见 `output/verification/`（01 起始、02 跟随、03 近景、04–06 暂停检查、07 胜利、08 超时、09 真实交付）。

## 源码结构

- `src/config.ts`：米制尺寸、出生点、三箱、三区、时间与容差。
- `src/textures.ts`：Canvas 程序化混凝土地面/墙面/木箱/危险条纹/标牌/仪表/贴花与共享材质。
- `src/models.ts`：叉车（含门架/货叉/轮组/驾驶室/鹈鹕）、货箱、静态合并工具。
- `src/world.ts`：仓库、货架、交付区、标识、灯光、碰撞体与静态几何合并。
- `src/main.ts`：渲染器/环境、Ammo 刚体、驾驶、货叉、拾取释放、交付判定、相机、HUD、状态机与调试观测接口 `window.__pelican`。
- `src/style.css`：界面视觉。
