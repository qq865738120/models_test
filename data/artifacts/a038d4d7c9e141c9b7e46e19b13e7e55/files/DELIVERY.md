# 交付说明 · 一万只鹈鹕的派单后台

## 交付物与启动

- 前端入口：`output/index.html`（相对路径加载 `output/assets/`，无外网请求，不使用 localStorage / IndexedDB / Service Worker）。
- 后端入口：`output/server/index.mjs`，仅使用 Node 内置模块，监听 `127.0.0.1` 并读取 `PORT`。
- 固定种子：`output/server/data/orders.json`，与 `materials/orders.json` 的 SHA-256 一致。
- 依赖版本、`materials/`、`tools/` 与既有配置均未修改。

```bash
# 与 HARNESS 一致：在 output 目录启动后端，端口由 PORT 指定
cd output
PORT=4174 node server/index.mjs        # 输出 DISPATCH_API http://127.0.0.1:4174

# 本地预览（开发工程内的 Vite preview 会把 /api、/health 代理到 4174）
npm run preview                        # 项目根目录执行
```

正式展示由工作台启动归档内的 `node server/index.mjs`，再把相对 `api/...` 与 `/health` 转发到该进程；前端不写死端口，也不依赖开发服务器。页面刷新会保留已派订单（数据在 Node 进程内存），只有重启 Node 进程才恢复固定种子；每页条数只保存在当前页面会话，刷新恢复 20 条。

## 实现概要

- **订单派送**：编号/客户/地址搜索、四状态筛选、真实总数与页码、边界翻页禁用、默认每页 20、只渲染当前页；仅本页 pending 可勾选，全选不包含其他状态；搜索/筛选/翻页清空选择并回第一页；批量派单确认弹窗展示数量、配送员、禁用原因与提交中状态；失败保留弹窗与选择可重试，成功后才清选择并重新请求列表、统计与已打开的详情。
- **详情抽屉**：独立 GET 请求、骨架加载、失败重试、Esc/遮罩/关闭按钮关闭；展示编号、客户、地址、状态、配送员、优先级、创建时间、contents、note 及明确空值占位。
- **总览**：四张真实统计卡与状态分布环图，点击待派单进入 pending 第一页并清空选择；统计只使用一次 `/api/stats` 快照。
- **配送员**：`GET /api/couriers` 三名固定配送员；“为TA派单”进入 pending 第一页预选配送员，仍需手动勾选并确认，不展示虚构运力或绩效。
- **运行报表**：真实状态数量/比例/快照时间、手动刷新；分母始终为全部订单；加载不显示伪 0，失败保留上次成功快照时间和数字并就近重试。
- **设置**：20/50/100 条每页；保存后回订单第一页并清选择；恢复默认只恢复 20 条，不撤销派单。
- **请求竞态**：列表、统计、详情均使用请求序号 + AbortController，仅最新请求可更新数据与加载/错误状态。
- **视觉与可访问性**：220px 深色侧栏、72px 顶栏、32px 内容内边距、56px 行高；统一按钮/标签/骨架/空态/错误态/Toast；模态与抽屉焦点圈、Esc 关闭、关闭后焦点归还，背景 `inert` 防误操作；390px 下表格内部横向滚动、整页不溢出；移动端主要触控目标 40px；支持 `prefers-reduced-motion`。
- **后端**：完整实现 `/health`、`/api/orders`、`/api/orders/:id`、`/api/couriers`、`/api/stats`、`POST /api/assign`；形状校验、重复查询参数/未知参数/非法百分号编码、64KiB 限制、整批存在性与 pending 校验、原子提交、并发 200/409 竞争；错误统一为 `{error:{code,message}}`，400/404/409/405/500 与契约一致。

## 实际运行的验证

以下检查均已在本地实际执行（Chrome headless + CDP 驱动真实点击，Vite preview 代理到打包后的 `output/server/index.mjs`）：

1. `npm run build`：`tsc --noEmit`、Vite 构建、`tools/package-server.mjs` 打包全部通过。
2. 接口自测 30 项，全部通过：health、订单默认/搜索/筛选/分页/越界页、详情、三名配送员、统计求和、派单成功、空/重复/超 100/非字符串/缺少字段/额外字段/错误配送员/错误 JSON/错误 Content-Type/超 64KiB 均 400、未知订单 404、非 pending 409、整批失败不产生部分修改、400/404/405 路径与错误结构、非法百分号/非法 UTF-8 路径 400、并发派同一单仅一个 200 另一个 409、重启后恢复种子（5000/2500/2500，PD-00001 pending）。
3. 浏览器主流程：默认 20 行 DOM、全选只覆盖本页 pending、取消弹窗保留选择、确认后 Node 状态与统计变化、详情字段与 Esc 关闭、页码/搜索/状态/菜单状态保留、设置 50 条与恢复默认、总览待派单深链、配送员“为TA派单”预选、报表快照、页面刷新保留已派订单、390×844 无页面横向溢出且表格内部横滚、抽屉/导航/弹窗可用。
4. 故障与竞态（本地测试代理延迟/503）：慢列表请求 A 无论成功或失败都不覆盖后发快请求 B 的列表/错误状态；派单返回 503 时弹窗、选择和已选配送员保留，重试成功后由真实 HTTP 提交；详情 503 后就近重试成功；统计失败时保留上次真实数字与快照时间并标注；列表刷新失败保留旧行并提供重试；409 冲突显示服务端错误、后台刷新真实状态且服务端保留成功方配送员；提交期间确认/取消/关闭均禁用且 Esc 无效；未使用 `alert`。
5. 焦点：取消弹窗后焦点回到触发按钮；成功提交后因触发按钮已禁用，焦点回到搜索框；关闭详情后焦点回到对应“详情”按钮。
6. 性能：按 `tools/performance.js` 相近口径（30 次输入、间隔 500ms、输入到下一绘制机会）在 1440×900 生产预览采样，输入反馈 P95 = **1.5ms**（不含 HTTP 等待）；默认 20 行，设置最大 100 行，不渲染全量 10,000 行。

## 已知限制与未完成项

- 浏览器实测仅使用 Chrome headless，移动端为 390×844 设备模拟，未在真实手机、Safari/Firefox 或屏幕阅读器上验证。
- 故障注入使用本地代理制造延迟与 503 响应，未做真实网络分区/杀进程级别的断连测试；派单请求没有前端超时，若网络长期悬挂，界面会保持“正在派单…”直到浏览器返回错误，避免在未知结果时伪造成功。
- 未编写自动化截图回归或像素比对；视觉检查通过实际截图与人工观察完成。
- 未主动制造 500 内部异常；统一错误处理分支通过代码审阅确认，接口自测覆盖了 400/404/405/409。
- 按要求无登录、权限、数据库、外部服务与持久化；服务重启后订单恢复固定种子，页面设置刷新后恢复默认 20 条。
